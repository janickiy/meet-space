# Аудит и оптимизация MeetSpace Admin — 5 ноября 2026

Область проверки: `admin/`, административные Go-маршруты и их зависимости,
PostgreSQL, Redis, Nginx/Compose и установщик. Проверялась фактическая архитектура:
React/TypeScript/Vite/TanStack Query; административные сессии находятся в
PostgreSQL, а не Redis. Пользовательское приложение проверялось на регрессии в
затронутых точках. Нагрузочные испытания проводились только на локальном
изолированном стенде с синтетическими данными.

## Проверки и воспроизводимость

Baseline до исправлений: Go tests, полный `-race`, `go vet`, 12 admin unit tests,
TypeScript/Vite build и installer tests проходили. Новые regression tests
воспроизвели перечисленные дефекты; исходный зелёный baseline не означал их
отсутствия. Неверный invite_code в новом SQL fixture и способ отправки browser
visibilitychange были исправлены в тестах и не объявлялись дефектами продукта.

После исправлений выполнены полный `go test -race ./...` с настоящей тестовой
PostgreSQL и `go vet ./...`, 23 admin unit tests и сборка, 39 пользовательских
frontend tests и сборка. Installer suite и отдельные Docker/Nginx проверки
включают отключённый listener, нестандартный порт и запрет административных
маршрутов через публичный канал.

`npm audit` (production и все зависимости) — 0 уязвимостей. `govulncheck` для
`cmd/api` и `cmd/admin` — 0 достижимых уязвимых символов. Обнаружены **не вызываемые
этим кодом** предупреждения GO-2026-6866/6860 (`x/net/html`) и GO-2026-5932
(`x/crypto/openpgp`). Это не названо полным отсутствием проблем в dependency tree;
необоснованное обновление всех общих библиотек не выполнялось.

```sh
go test ./...
go test -race ./...
go vet ./...
go run golang.org/x/vuln/cmd/govulncheck@latest -show verbose ./cmd/api ./cmd/admin
python3 -m unittest discover -s scripts/install -p 'test_*.py'
RUN_ADMIN_PROXY_TESTS=1 ADMIN_PROXY_TEST_IMAGE=your-built-proxy \
  python3 -m unittest discover -s scripts/install -p 'test_admin_proxy.py'
cd admin && npm test && npm run build
npm run test:browser
npm run test:browser:cycles
npm run test:browser:soak
```

PostgreSQL integration требует `MEETSPACE_AUDIT_POSTGRES_DSN`: только loopback,
пустая disposable БД и ограниченные имена. Дополнительно разрешены `audit_backend`
и `audit_resources` для независимых параллельных прогонов. Без DSN интеграционные
тесты пропускаются; такой запуск не заменяет прогон с БД. Browser scripts требуют
доступный Playwright/Chrome, описанный в `admin/README.md`.

`scripts/admin-audit-load.py` принимает синтетические credentials JSON по stdin;
никогда не записывает cookie/пароль в результаты. Разрешён только отдельный
loopback HTTPS-порт, максимум 5000 запросов, 16 workers и 50 запросов/с. В этом
аудите используются 1200 запросов, 8 workers, 40 запросов/с и 20k тестовых users.
Отчёт содержит только operation, status counts и latency percentiles. Raw logs,
EXPLAIN, pprof и browser measurements находятся в локальном ignored
`tmp/admin-audit/`; production-данные в них не используются.

## Изменённые области и ограничения

Изменения: `admin/src/`, unit/browser tests и README; domain/usecase/admin;
административные HTTP/PG repositories и tests; `internal/app/admin_resources.go`;
HTTP readiness client; миграция **000040_administrator_search_indexes**;
proxy negative tests; изолированный load script. Миграции 38/39 первоначальной
админки сохранены. Добавлены audit actions `*_failed` с metadata `httpStatus`;
основные URL/payload API совместимы. Развёртывание и recovery описаны в
[ADMIN_DEPLOYMENT_RU.md](ADMIN_DEPLOYMENT_RU.md).

- При недоступном PostgreSQL нельзя гарантировать durable failure audit:
  выполняется ограниченная попытка и generic log. Success audit остаётся атомарным
  с изменением БД. Дополнительный внешний audit sink не вводился.
- Уже начавшаяся авторизованная транзакция удерживает права до завершения;
  revoke ждёт её, после завершившегося revoke задержанные writes отклоняются.
- SQL и S3 не имеют общей транзакции: существующее удаление файлов идемпотентно
  при повторе. Ошибка storage откатывает метаданные/аудит, но уже удалённые внешние
  объекты автоматически не восстанавливаются. Это ограничение прежнего механизма.
- Argon2id уже ограничен двумя admin workers (по 64 MiB рабочего буфера), очереди
  нет. 429 при пиковой конкуренции ожидаем. Это не предел всего Go RSS; public
  auth имеет отдельный бюджет. Для обновляемого хоста выбран лимит API 512 MiB,
  соответствующий текущему production Compose, вместо прежних 256 MiB.
  На изолированном стенде с **512 MiB и без swap** три волны из двух public и двух
  admin входов (12 запросов) дали 6 ожидаемых public 401 и 6 admin 200, без
  transport/500/429/OOM и рестартов. Sampled peak RSS — 446025728 B (~425,4 MiB),
  readiness после проверки 200. Нехватка памяти на прежних 256 MiB не
  воспроизводилась: этот риск не объявляется подтверждённым OOM. Общий
  `Retry-After:900` также применяется к
  кратковременной занятости KDF (P3 UX-ограничение).
- При сетевой ошибке logout клиент очищает локальную сессию, но не может
  подтвердить серверный отзыв HttpOnly cookie. Если Session Storage запрещён,
  флаг явного выхода не переживёт reload.
- В первоначальной версии настройки были read-only; реализация редактирования
  от 6 ноября описана в конце отчёта. Отсутствующие host CPU/RAM/storage-capacity
  метрики не заменяются фиктивными числами. Dashboard TTL — 10 секунд.
- Долговременная общая нагрузка public auth + admin (кроме указанного короткого
  совместного smoke), полный WebRTC call/recording
  media E2E, все браузеры и чистая интерактивная Linux-установка не охвачены этим
  аудитом. Существующие автоматические тесты проходят; это не заменяет такие
  эксплуатационные проверки.

## Итоговый стенд и публикация

Настоящий HTTPS E2E прошёл: вход, все разделы, поиск/блокировка/разблокировка
синтетического пользователя, создание отдельного администратора и вход им,
блокировка и немедленный 401/login UI, разблокировка/удаление, аудит, публичный
404 и logout/reload. Созданные аккаунты удалены, исходное состояние восстановлено,
JavaScript errors 0.

Отдельная проверка с настоящим зарегистрированным обычным пользователем:
его public bearer действителен на пользовательском API (200), но bearer,
