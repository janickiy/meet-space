# LDAP и Active Directory

MeetSpace поддерживает один каталог LDAP для корпоративного входа и синхронизации пользователей. На странице входа используются общие поля **Email** и **Пароль**, без выбора провайдера. Во вкладке «LDAP / Active Directory» административной панели задаётся один из двух режимов:

- **Локальные аккаунты** — пароль проверяется в MeetSpace, доступны создание аккаунта и восстановление пароля.
- **Только LDAP** — пароль проверяется в каталоге; создание аккаунта и восстановление пароля через MeetSpace отключены в интерфейсе и API. Пользователи управляют корпоративным паролем средствами своей организации.

Режимы взаимоисключающие. Неверный LDAP-пароль или недоступность каталога не приводят к попытке локального входа. Отдельная учётная запись административной панели остаётся способом доступа администратора в обоих режимах. Порядок работы с настройками описан в [руководстве администратора](operations/admin.md).

## Настройка подключения

Подключение допускает `ldaps://` либо `ldap://` с обязательным StartTLS. MeetSpace проверяет имя сервера в сертификате и цепочку доверия. Если CA внутренний, вставьте его PEM сертификат в поле «CA сертификат PEM»; отключения проверки TLS нет. Адрес не должен содержать логин, пароль, путь или параметры запроса. Backend должен иметь сетевой доступ к каталогу.

Создайте отдельную учётную запись bind с минимальным правом чтения пользователей и групп. Пароль сохраняется в `platform_settings.ldap_bind_password_ciphertext` зашифрованным отдельным AAD; для записи и чтения требуется `PROVIDER_TOKEN_ENCRYPTION_KEY` на сервере. Браузер получает только признак наличия пароля. Пустое поле пароля при сохранении оставляет текущий секрет. Текст пароля не записывается в JSON настроек или аудит.

Укажите базовый DN, DN пользователей, фильтр пользователей и DN **группы доступа**. DN пользователей и группы должны совпадать с базовым DN или находиться внутри него. Проверка подключения и синхронизация проверяют существование областей пользователей и группы. Войти и попасть в синхронизацию могут только члены этой группы. Для AD вложенное членство включается отдельным переключателем; оно использует правило Active Directory `1.2.840.113556.1.4.1941`. Для обычного LDAP применяется прямое членство через `memberOf`. Вход по логину экранирует управляющие символы LDAP фильтра. Не используйте в качестве группы доступа слишком широкую группу.

| Поле | Active Directory | OpenLDAP / LLDAP |
| --- | --- | --- |
| Фильтр пользователей | `(&(objectClass=user)(!(objectClass=computer)))` | `(objectClass=person)` |
| Атрибут логина | `sAMAccountName` | `uid` |
| Неизменяемый ID | `objectGUID` | `entryUUID` |
| Email / имя | `mail` / `displayName` | `mail` / `cn` |
| Членство | `memberOf` | `memberOf` |

Атрибуты можно изменить под схему конкретного каталога. **Не меняйте атрибут неизменяемого ID после первой синхронизации**: он связывает запись каталога с аккаунтом MeetSpace. Совпадение email само по себе никогда не объединяет LDAP и локальный аккаунты; конфликт требует решения администратора. Для AD клиент также проверяет `userAccountControl` и `accountExpires`; отключённые или истёкшие аккаунты не допускаются к входу. Если любой из этих атрибутов не читается, снимок отклоняется целиком.

В единой форме пользователь вводит значение настроенного **атрибута email** (`mail` по умолчанию), например `test01@meetspace.test`. Оно должно однозначно определять запись каталога. Атрибут логина (`uid` или `sAMAccountName`) сохраняется для синхронизации и сопоставления профиля; он не заменяет email в форме входа.

## Проверка и синхронизация

Сначала сохраните параметры, затем выполните «Проверить подключение». Проверка читает каталог через TLS, bind и первую страницу поиска (до 500 записей); она не меняет пользователей. Показанное число — количество **проверенных записей первой страницы** из группы доступа, а не полный размер каталога. Ноль допустим, но последующая синхронизация отключит ранее связанные аккаунты. Для корпоративного входа и запуска синхронизации выберите режим «Только LDAP» и сохраните изменения.

«Синхронизировать сейчас» ставит фоновое задание; периодический запуск использует интервал из настроек. Задание выполняет `product-worker`. Полный снимок ограничен 10 000 записей; при ошибке страницы, отсутствии ожидаемого атрибута, дубликате ID/логина/email или неполном ответе изменения не применяются. Успешный снимок обновляет email и имя LDAP аккаунтов, создаёт новых участников группы и отключает тех, кто вышел из неё или отключён в AD. Аватар пользователя остаётся локальной настройкой.

Смена режима завершает сеансы пользователей, для которых выбранный способ входа больше не разрешён. Изменение параметров безопасности каталога отзывает действующие LDAP-сессии и устаревшие токены. Возвращение к прежнему режиму не восстанавливает отозванные сеансы. Учётные записи и данные сохраняются; сеансы отдельной административной панели не отзываются. Статус и ошибки синхронизации видны в административной панели без паролей и содержимого записей каталога.

## Локальный стенд LLDAP

[Тестовый стенд](../tools/ldap-dev/README.md) работает на Mac через Docker и проверен по LDAPS. Для backend на Mac используйте `ldaps://127.0.0.1:6360`; для API в общей Docker сети `meetspace-ldap-test` — `ldaps://ldap:6360`. В поле CA вставьте содержимое `tools/ldap-dev/secrets/tls/ca.crt`.

- Тип каталога: **OpenLDAP / LLDAP**; базовый DN `dc=meetspace,dc=test`.
- DN пользователей: `ou=people,dc=meetspace,dc=test`.
- Bind DN: `uid=svc-meetspace,ou=people,dc=meetspace,dc=test`; пароль из локального `secrets/credentials.json`.
- DN группы: `cn=meetspace-users,ou=groups,dc=meetspace,dc=test`.
- Фильтр `(objectClass=person)`; атрибуты `uid`, `entryUUID`, `mail`, `cn`, `memberOf`; вложенные группы выключены.
- `alice` и `bob` состоят в группе; `outsider` существует, но не состоит в ней.

LLDAP проверяет общий LDAP протокол и локальную интеграцию. Он не воспроизводит `objectGUID`, `userAccountControl` и поведение AD. Подключение к настоящему Windows Active Directory этим стендом не проверено; перед рабочим использованием отдельно проверьте сертификаты, схему, вложенные группы, срок действия аккаунта и синхронизацию в целевом домене.

## Проверки для разработчика

Проверка чтения каталога и входа без изменения стенда:

```bash
LDAP_DEV_INTEGRATION=1 go test ./internal/infrastructure/ldap -run TestLocalLLDAPReadOnly -count=1
```

Сквозной тест `TestLocalLDAPEndToEnd` использует настоящие HTTP-обработчики, LDAP и PostgreSQL. Для него задайте `LDAP_DEV_E2E=1` и `MEETSPACE_AUDIT_POSTGRES_DSN` с адресом **отдельной пустой БД** `meetspace_ldap_e2e` на `127.0.0.1` или `localhost`. Рабочую БД указывать нельзя: тестовый помощник проверяет имя, loopback-адрес и отсутствие пользовательских таблиц, создаёт временную схему и удаляет её после проверки.

```bash
LDAP_DEV_E2E=1 go test ./internal/infrastructure/postgres -run TestLocalLDAPEndToEnd -count=1 -v
```

Тест временно исключает `alice` и `bob` из тестовой группы и восстанавливает членство при завершении. Проверяются сохранение зашифрованных параметров, CSRF и ревизии, импорт до первого входа, SID и обновление сеанса, отзыв доступа, пустая группа, возвращение с прежним ID и недоступность LDAP. Эти проверки следует запускать на выделенном стенде, без параллельного изменения той же группы.
