# Добавление, переключение и удаление аккаунтов

В общем окне «Настройки аккаунта» есть раздел «Аккаунты». Можно войти
в существующий аккаунт или зарегистрировать новый, подключить до пяти аккаунтов
и выбрать текущий. Список относится к этому браузеру. Пароли не сохраняются;
долговременные секреты передаются серверу через HttpOnly/SameSite=Lax cookie
с `Secure` вне локального окружения. JavaScript не читает эти секреты.

POST `/api/v1/auth/accounts/list` возвращает подтверждённые сервером профили;
POST `/api/v1/auth/accounts/switch` принимает `userId` и требует cookie именно
этого аккаунта. Идентификатор сам по себе не даёт доступа. Запрос обновления JWT может
содержать `userId`, чтобы другая вкладка не переключила аккаунт во время обновления.
Вход не отзывает сессии других добавленных аккаунтов. Повторный вход в тот же
аккаунт заменяет его прежнюю сессию в этом браузере, сохраняя другие устройства. Выход отзывает выбранную
сессию. Cookie имеют прежний путь `/api/v1/auth`; миграция действующих сессий
выполняется при обычном восстановлении входа. Изменения схемы не требуются.

Смена пользователя отменяет запросы, очищает QueryClient и размонтирует
интерфейс предыдущего пользователя вместе с WebSocket, видео, аудио и
предпросмотром. Другие вкладки этого браузера обновляются; между вкладками
передаются только публичный ID и одноразовый идентификатор события.

DELETE `/api/v1/auth/me` принимает пароль текущего аккаунта. UUID из запроса
не используется. В интерфейсе требуется подтверждение необратимости. Неверный
пароль возвращает 422 и сохраняет вход. Ограничение: 5 попыток в минуту на IP.
Гости не могут удалить зарегистрированный аккаунт.

Удаление в одной транзакции очищает профиль, данные входа, уведомления, папки,
подключения календаря, push-устройства и отзывает все сессии на всех устройствах.
Новый аккаунт без связанной общей истории физически удаляется из `users`.
Если другие пользователи имеют связанную историю, сохраняется обезличенная
техническая строка: адрес `deleted.<UUID пользователя>@invalid`, не содержащий
прежний email,
пустой хеш пароля, имя «Удалённый аккаунт», отсутствие административной роли.
Войти под такой учётной записью нельзя. Она не появляется в поиске, не получает
приглашений и не участвует в новых звонках. Повторная регистрация старого email создаёт
новый UUID и не возвращает прежнюю историю. Общие сообщения и записи других
участников не удаляются. Аккаунт выходит из групп, которыми не владеет.

Удаление возвращает `409`, пока пользователь владеет действующей группой,
незавершённой встречей или участвует в звонке/конференции. Интерфейс объясняет,
что сначала нужно передать владение группами или удалить их, завершить/отменить
встречи и выйти из звонков. Это сохраняет управление общими ресурсами.
После удаления выбирается другой подключённый аккаунт, если он доступен;
иначе открывается вход. Ошибки сети не восстанавливают удалённую личность.

## HTTP-контракт

| Метод и путь | Авторизация и запрос | Успех / ошибки |
| --- | --- | --- |
| `POST /api/v1/auth/accounts/list` | Cookies `meetrix_account_<UUID>`; пусто или `{}` | `200 {status,items:User[]}`; недействительные cookies удаляются |
| `POST /api/v1/auth/accounts/switch` | Cookie выбранного аккаунта; `{userId}` — канонический UUID | `200 {status,accessToken,tokenType,expiresIn,user}`, активная cookie; `401` нет сессии, `403` другой владелец, `422` UUID |
| `POST /api/v1/auth/refresh` | Cookie; пусто либо `{userId}` | Новый JWT и cookie; `401` сессия отозвана/отсутствует |
| `POST /api/v1/auth/logout` | Cookie, необязательный Bearer; пусто либо `{userId}` | `200 {status:"success"}`; идемпотентный выход выбранного аккаунта |
| `DELETE /api/v1/auth/me` | Bearer текущего аккаунта; `{password}` | `200 {status:"success"}`; `422` пароль, `409` активность/владение/конфликт, `403` гость |

Операции авторизации проверяют точное значение Origin из `PUBLIC_FRONTEND_URL`; запрещён
`Sec-Fetch-Site: cross-site`. Непустое тело требует `application/json` (`415`),
неизвестные поля запрещены (`400`). Превышение пяти сохранённых аккаунтов — `409`.
Ответы не содержат секрет для обновления сессии (refresh secret). Поля User: `id,email,displayName,isAdmin,
createdAt,updatedAt`. Гостевая область доступа (scope) возвращается только для гостя.
