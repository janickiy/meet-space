# Постоянная авторизация аккаунтов

После входа пользователь остаётся в аккаунте без тайм-аута простоя или
автоматического выхода через час. Явный выход отзывает текущую браузерную сессию.
Отдельный вход с другого устройства создаёт независимую сессию.

## Хранение и HTTP

- Access JWT действует 3600 секунд. Содержит `sid`; API проверяет
  соответствие сессии пользователю и отсутствие отзыва в PostgreSQL.
- Login возвращает `LoginResponse` и устанавливает host-only cookie
  `meetrix_session` и `meetrix_account_<UUID>`, `HttpOnly`, `SameSite=Lax`,
  `Secure` вне локальных `APP_ENV=local|dev|debug` (HTTPS сама не меняет флаг),
  `Path=/api/v1/auth`. Секрет — 256 случайных бит; в БД хранится только SHA-256.
- Браузерный срок cookie — 400 дней, обновляется при refresh. Серверная сессия
  не имеет срока истечения. Очистка cookies самим пользователем или браузером
  требует нового входа.
- `POST /api/v1/auth/refresh` с пустым телом, `{}` либо `{userId}` принимает
  cookie и выдаёт новый access JWT. `userId` выбирает cookie нужного аккаунта
  и проверяется против её владельца; frontend всегда указывает текущий аккаунт.
  `POST /api/v1/auth/session` мигрирует действующий JWT предыдущего выпуска, требует
  Bearer и запрещён гостям. Оба ответа имеют `Cache-Control: no-store`.
- `POST /api/v1/auth/logout` идемпотентен, принимает cookie и необязательный Bearer,
  включая просроченный; JSON может содержать `userId`. Отзывает выбранную
  сессию и удаляет её cookie, сохраняя входы остальных аккаунтов браузера. Ранее выданные JWT этой
  сессии отклоняются сразу. Старый JWT тоже получает серверную отметку отзыва.
- Cookie-операции проверяют точное равенство Origin и `PUBLIC_FRONTEND_URL`
  (схема/host/порт) и отклоняют `Sec-Fetch-Site: cross-site`. При непустом теле
  обязателен `Content-Type: application/json`; CLI без Origin и Fetch Metadata
  допускается. Cookie не используется
  для авторизации остальных маршрутов: они требуют Bearer.
- Гостевой JWT имеет часовой срок и область одной встречи.
  Постоянная авторизация применяется к зарегистрированным аккаунтам.

## Интерфейс и конференция

Клиент обновляет JWT за минуту до истечения и повторяет один запрос после 401.
Параллельные запросы разделяют одно обновление. При смене пользователя или выходе
запоздалый ответ не восстанавливает прежнюю авторизацию. Профиль и короткий JWT
кэшируются в `sessionStorage`; секрет cookie недоступен JavaScript.

Сеть/5xx не очищают профиль или кэш и не размонтируют конференцию. Обновление
повторяется при focus/online/возврате на вкладку и каждые 30 секунд.
После закрытия браузера аккаунт восстанавливается через cookie. Явный выход
сразу очищает интерфейс; локальная отметка выхода блокирует восстановление из
cookie при временно недоступном сервере и распространяется на другие вкладки.

WebSocket зарегистрированного аккаунта привязан к серверной сессии. Исходный
JWT может истечь без смены `connectionId` и медиапривязки. Каждый подтверждённый
pong и команда проверяют отзыв сессии. Отказ хранилища завершает соединение с
`authentication_unavailable`; клиент может переподключиться. Отзыв завершает
соединение с `authentication_revoked`. Гостевые/старые WS без `sid` сохраняют
проверку срока JWT. SSE уведомления ограничены сроком короткого JWT и
восстанавливаются с новым токеном; отзыв проверяется перед событием/keepalive.

## Хранение сессий

Миграция `000026_persistent_auth_sessions.up.sql` добавляет три таблицы:
`auth_sessions`, `auth_session_tokens`, `auth_legacy_tokens`. Старые таблицы
и данные не меняются. Отметки отзыва предотвращают гонку logout со старым
bootstrap; конкурентные вкладки используют одну сессию и отдельные хэши cookie.
Перед применением нужен backup PostgreSQL. Откат API не выполняет DB down.

## Несколько аккаунтов и восстановление

В одном браузере поддерживается до пяти аккаунтов. `/auth/accounts/list` и
`/auth/accounts/switch` используют только подтверждённые сервером cookie.
Повторный login в тот же аккаунт отзывает прежнюю сессию этого браузера;
другие аккаунты и другие устройства сохраняют вход. Переключение пользователя
очищает запросы, кэши и соединения прежней личности. Долговременные секреты
не передаются в JSON или межвкладочные сообщения. Подробнее:
[account-management.md](account-management.md).
