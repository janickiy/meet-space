# Групповые чаты

Группы — самостоятельные `conversations.type='group'`, доступные в разделе «Личные». Фильтры **Все / Личные / Группы / Новые** не создают разные хранилища сообщений. Чат встречи остаётся частью конференции. Группы можно добавлять в личные [папки](PERSONAL_FOLDERS.md).

## Схема и правила

Миграция **30** добавляет к существующей модели Conversation имя, описание, создателя, версию метаданных, необязательные ключ и версию приватного аватара, признак логического удаления и ключ идемпотентного создания. UUID переписки не меняется. Сохраняются общие таблицы `conversation_messages` и `conversation_attachments`, ответы на сообщения (reply), указатель прочитанного (read cursor) и версии сообщений. Отдельных `group_messages` и `folder_id` нет.

`conversation_members` получает `role=owner|admin|member` и `left_at`. Строки вышедших и исключённых участников сохраняются, чтобы внешние ключи (FK) продолжали ссылаться на авторов истории. Первичный ключ (PK) исключает дублирование пользователя. Частичное ограничение уникальности и отложенная проверка обеспечивают одного действующего владельца и не более 100 действующих участников. Для личной переписки (direct) сохраняются уникальность пары и требование ровно двух пользователей.

Имя содержит 1–50 символов Unicode, описание — до 200 символов с переносами строк. Составные эмодзи поддерживаются. NUL, неподдерживаемые управляющие символы и символы управления направлением текста (bidi controls) запрещены. Группы доступны только зарегистрированным аккаунтам: гость (guest) не может создать группу, вступить в неё или получить её сообщения и файлы.

История общая: новый участник видит существующие сообщения. При первом добавлении указатель прочитанного устанавливается на текущую границу истории, поэтому старые сообщения не увеличивают счётчик непрочитанного. При возвращении указатель сохраняется, а роль становится member. Счётчики, списки и рассылка событий учитывают только действующих участников неудалённой группы.

| Действие | owner | admin | member |
|---|---|---|---|
| Сообщения, файлы, история, отметки прочтения | Да | Да | Да |
| Изменение и удаление своего сообщения | Да | Да | Да |
| Имя, описание, аватар | Да | Да | Нет |
| Добавить пользователей | Да | Да | Нет |
| Удалить обычного member | Да | Да | Нет |
| Удалить admin, назначить/снять admin | Да | Нет | Нет |
| Передать владение, удалить группу | Да | Нет | Нет |
| Выйти | После передачи, если есть другие | Да | Да |

Передача превращает прежнего owner в admin. Последний owner при выходе закрывает группу. Удаление группы атомарно закрывает доступ всем и скрывает её из списков. Сообщения и прикреплённые файлы сохраняются в рамках существующей политики истории; логическое удаление (soft-delete) не означает немедленного физического удаления истории. Текущий аватар удалённой группы подлежит очистке.

## REST

Все пути имеют префикс `/api/v1` и требуют Bearer-авторизацию зарегистрированного аккаунта. Ответы используют private/no-store; частота запросов ограничена. Сервер сам определяет пользователя и его роль.

| Метод и путь | Назначение и тело запроса |
|---|---|
| `GET /conversations` | Общий список; `type=direct\|group`, `unreadOnly=true`, `search`, `before`, `limit` |
| `GET /conversations/:id` | Данные переписки для текущего участника |
| `PATCH /conversations/:id/preferences` | `{notificationsEnabled}` — настройка уведомлений только текущего участника |
| `POST /conversations/group` | `{clientRequestId,name,description,memberIds}`; создатель добавляется owner |
| `PATCH /conversations/:id` | `{name?,description?}` |
| `GET /conversations/:id/members` | `{status,items:[{id,displayName,role,online}]}`; до 100, owner/admin/member порядок |
| `POST /conversations/:id/members` | `{userIds}`; повторный запрос не создаёт дубликат участника |
| `DELETE /conversations/:id/members/:userId` | Исключение с сохранением исторической строки |
| `PATCH /conversations/:id/members/:userId` | `{role:"admin"\|"member"}` |
| `POST /conversations/:id/ownership` | `{userId}` текущего участника |
| `POST /conversations/:id/leave` | `{}` |
| `DELETE /conversations/:id` | Закрытие группы владельцем |
| `PUT /conversations/:id/avatar` | Бинарное содержимое JPEG/PNG до 2 MiB |
| `DELETE /conversations/:id/avatar` | Очистка ссылки на текущий аватар |
| `GET /conversations/:id/avatar/content` | Приватные байты текущего аватара |
| `GET /conversations/:id/attachments/:attachmentId/content` | Приватные байты прикреплённого файла группы |

Сообщения, ответы, редактирование, удаление, курсоры истории, отметки прочтения и этапы работы с вложениями (init/upload/finalize/download) используют общие маршруты `/conversations/:id/...`. Нельзя отвечать на сообщение, использовать файл или отметку прочтения из другой переписки. Роль в группе не даёт права изменять или удалять чужие сообщения.

Создание и изменение возвращают `{status,item}`. Новая группа получает ответ 201, повтор с теми же clientRequestId и телом — 200, другое содержимое с тем же ключом — 409. Выход и удаление возвращают `{status}`. Курсор списка привязан к пользователю и фильтрам. Название, число участников, последний отправитель, превью и счётчик непрочитанного выбираются без отдельного SQL-запроса к каждой группе. Общий индикатор непрочитанных сообщений учитывает direct и group.

## События реального времени и уведомления

Общий WebSocket пользователя работает через Redis Pub/Sub независимо от сессии конференции и SFU:

- `message.created|updated|deleted`: `{conversationId,type,message}`;
- `conversation.updated`: `{conversationId,type}`;
- `conversation.member.added|updated|removed`: `{conversationId,type,userId,role?}`;
- `conversation.read.updated`: `{conversationId,type,state}`.

Данные сохраняются до публикации события. Создание группы отправляет одно обновление состава всем действующим участникам. Добавление участников и изменение ролей сопровождаются событиями соответствующих изменений. Исключённый пользователь получает только событие удаления без сообщений и метаданных. Повторная отправка не создаёт второе уведомление о сообщении. Общая модель message содержит clientRequestId; ожидающая подтверждения строка клиента сопоставляется с UUID запроса **и автором**.

Перед отправкой отложенных данных WebSocket сервер повторно проверяет участие пользователя. Общая блокировка переписки удерживается на время ограниченной по длительности записи в сокет; исключение участника требует исключительной блокировки. После завершения исключения накопленные события ему не отправляются. История, отметки прочтения REST и DTO записи формируются с тем же порядком блокировок: после потери прав новая история недоступна.

Redis Pub/Sub остаётся механизмом уведомления, а PostgreSQL — источником состояния. После переподключения или пропуска события клиент заново получает данные REST. Подтверждённый сервером отказ 403/404 закрывает группу и очищает приватные кэши. Сохраняются индикатор непрочитанного и всплывающие уведомления личных сообщений. Отдельная email-рассылка для каждого группового сообщения не добавляется.

Статус присутствия относится к аккаунту и учитывает все его вкладки. Для списка участников выполняется одна групповая проверка присутствия. Если Redis недоступен, возвращается `online=null`, а интерфейс показывает неизвестный статус. У самой группы статуса «в сети» нет.

## Приватные файлы и ресурсы

Для вложений действуют ограничения размера и содержимого, временное право загрузки (lease), подтверждение завершения (finalize) и закрытый бакет. Для скачивания из группы выдаётся адрес API с `authenticated:true`, а не ссылка, сама по себе дающая доступ к MinIO. При каждом запросе содержимого проверяется действующее участие в группе. Личные переписки и конференции (direct/conference) используют подписанные ссылки.

Браузер получает файлы и аватары через Bearer fetch → Blob/ObjectURL; JWT не передаётся в параметрах URL (query). При удалении компонента или потере доступа запросы отменяются, а Object URL освобождаются. Общая очередь загрузки аватаров ограничена 6 запросами. После HTTP429 допускаются не более двух повторов; удаление компонента отменяет ожидание. Уже скачанное содержимое отозвать невозможно. Начатая авторизованная передача завершается или отменяется до фиксации удаления участника. Передача ограничена 30 секундами и общим пулом из 8 операций на API. Долгая передача может задержать изменение переписки, пока удерживается общая блокировка.

Аватары поддерживают JPEG/PNG, до 2 MiB и 2048×2048. Сервер декодирует и заново кодирует изображение, удаляя метаданные и добавленные байты. SVG, WebP и внешние URL не принимаются. На API допускаются не более двух одновременных загрузок.

Миграция **31** создаёт постоянный реестр объектов `conversation_avatar_objects` со состояниями pending → active → retired/cleaning → cleaned. Объект регистрируется до отправки MinIO; прерванные загрузки, замены и удалённые группы очищаются ограниченными порциями. Процедура очистки не удаляет текущий аватар и не может активировать уже захваченный для удаления объект. Очищенные записи старше семи дней удаляются ограниченными порциями; неочищенные и текущие ссылки сохраняются.

## Совместимость и связанные возможности

При откате API должен сохранять проверки активного членства и типа переписки.
Версия без этих проверок может открыть историю исключённым участникам;
используйте [процедуру отката](ROLLBACK.md).

Обратная миграция (down) 30 запрещена, пока существуют группы; down 31 — пока есть неочищенные объекты или ссылки на текущие аватары. Откат отдельных ранних миграций в текущей схеме с папками, звонками и закреплениями
не является готовым способом возврата к прежней версии; требуется согласованный план всего выпуска. История конференций хранится отдельно.

Папки уже ссылаются на direct/group UUID через `folder_conversations`.
Общие закрепления сообщений реализованы: до 20 на переписку, управлять ими может
любой действующий участник. Поиск сообщений и переход к контексту работают в
группах: [personal-chat-search.md](personal-chat-search.md).
Личные звонки доступны между двумя аккаунтами; групповых звонков из чата нет.
Настройка `PATCH /conversations/:id/preferences {notificationsEnabled}` доступна
каждому участнику группы и меняет только его уведомления, сохраняя счётчик непрочитанного.
Персональные `/clear-history` и `/hide` относятся только к direct.
Архивация и «пометить непрочитанным» не реализованы.

## Ошибки

`401` — токен/сессия, `403` — роль или утрата членства, `404` — недоступная группа,
`409` — конфликт создания/владения/лимитов, `422` — поля/UUID/курсор,
`429` — превышение частоты запросов. При загрузке дополнительно проверяются MIME-тип,
размер и содержимое. Не повторяйте загрузку отклонённого файла без исправления причины.
