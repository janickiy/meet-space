# Данные и внешние передачи

Актуализировано 29 октября 2026 года.

Это техническая инвентаризация текущего приложения. Она не задаёт юридические
основания обработки, сроки хранения организации, согласия участников или
договоры с провайдерами. Эти решения должен отдельно зафиксировать владелец
развёртывания перед включением внешних интеграций.

## Что хранится

| Данные | Где находятся | Доступ и жизненный цикл |
| --- | --- | --- |
| Аккаунт: UUID, email, имя, даты, `is_admin` | PostgreSQL `users` | Серверная авторизация; пароль хранится как Argon2id hash с солью, исходный пароль не сохраняется |
| Авторизация и предпочтения устройств | Короткий JWT и профиль в `sessionStorage`; секрет сессии в HttpOnly cookie; SHA-256 секрета и отзыв в PostgreSQL; настройки устройств и отметка явного выхода в локальном хранилище браузера | Серверная сессия аккаунта без тайм-аута; logout отзывает её и связанные JWT. Пароль и секрет cookie в JS/логи не передаются; device ID не входит в серверную телеметрию |
| Встречи, расписание, membership, допуск, роли, модерация | PostgreSQL | Участие и допуск проверяются при обращении; UUID/ссылка не заменяют проверку прав |
| Соединения и маршруты, билеты, leases, ограничения частоты | Redis; сведения participant sessions также в PostgreSQL | Redis-данные временные и имеют TTL; Pub/Sub не является устойчивой историей |
| Сообщения, ответы, версии, прочтение | PostgreSQL `chat_messages`, `chat_read_states` | Допущенное членство; удаление сообщения обнуляет его текущий текст и оставляет tombstone; старые резервные копии живут отдельно |
| Вложения: имя, размер, MIME, checksum, статус | Метаданные в PostgreSQL; приватные байты в S3-хранилище | До 10 МиБ; скачивание после проверки доступа по короткоживущей ссылке; незавершённые вложения имеют очистку, привязанные не имеют общего автоматического срока удаления |
| Записи, сегменты, статусы, поколения и аренды | PostgreSQL; временный spool на диске recorder; готовые объекты в S3-хранилище | Финальные аудио/видео, превью и архивы выдаются по проверенным метаданным поколения; bucket приватный |
| Уведомления, предпочтения, jobs и доставка | PostgreSQL | Личные получатели, ссылки на ресурсы, состояния и безопасные коды ошибок; уведомление не предоставляет права на ресурс |
| OAuth и push tokens | PostgreSQL, ciphertext AES-GCM | Независимый ключ `PROVIDER_TOKEN_ENCRYPTION_KEY`; клиентские ответы не раскрывают токены; при revoke локальные ciphertext удаляются, резервные копии могут их сохранять |
| OAuth state и PKCE verifier | PostgreSQL | Одноразовый state со сроком доступа 10 минут; очистка использованных/истёкших строк выполняется фоновыми ограниченными порциями |
| Диагностика и метрики | stdout/journal контейнеров, Prometheus | Метрики используют ограниченные категории; журналы могут содержать технические entity IDs и IP соединения в proxy access log, но не должны содержать тела чата, SDP, JWT и подписанные query |
| Ошибки frontend | Проверенный JSON в API log и агрегированный счётчик Prometheus при включённой телеметрии | Версия, шаблон маршрута, код, семейство браузера, до пяти координат в собственном JS; без исходного сообщения, query, токенов, содержимого встречи и идентификатора пользователя |

Медиа в браузере передаётся по WebRTC; TLS защищает публичные HTTP/WSS-запросы.
SFU принимает медиа, а серверная запись имеет доступ к его
содержимому. Это не заявленная end-to-end encryption между участниками,
скрывающая содержимое от сервера.

## Внутренние маршруты медиа и команд

Браузер отправляет Opus/VP8 по WebRTC напрямую в SFU либо через Coturn.
API передаёт SDP/ICE и команды по WS/защищённому HTTP; RTP через API и RabbitMQ
не проходит. SFU передаёт record-worker защищённый HTTP NDJSON
поток: метаданные и RTP в поле JSON `rtp` (base64). SFU не декодирует эти пакеты.
Recorder депакетизирует их в IVF/Ogg на локальном `/storage/records/{recordId}`,
FFmpeg создаёт сегменты и итоговый файл записи.

`recording_outbox` и запись создаются в одной PostgreSQL-транзакции. RabbitMQ
доставляет `record.start`/`record.stop`, Redis — временные события для WS/SSE,
`background_jobs` — постоянные продуктовые задания. Это разные каналы с разной
устойчивостью; подтверждение RabbitMQ не означает готовность медиафайла.

Сервис Compose `minio` может быть классическим MinIO либо SeaweedFS из hardened
установщика. Оба предоставляют приватный S3 API; `MINIO_*` — имя совместимой
конфигурации. Локальный spool recorder не является S3-томом и требует отдельного
учёта места/очистки. Состав поставки: [ARCHITECTURE.md](ARCHITECTURE.md).

## Какие данные могут покинуть развёртывание

По умолчанию внешние адаптеры имеют режим `noop`. `mock` разрешён только в локальном/test окружении и выдаёт помеченные
демонстрационные результаты. Адреса сервисов и секреты задаёт оператор;
пользователь не передаёт произвольный endpoint для серверного запроса.

| Получатель | Условие | Передаваемые данные | Обратные данные |
| --- | --- | --- | --- |
| SMTP сервер | `EMAIL_PROVIDER_MODE=smtp` и подходящее письмо | Адрес получателя, тема, текст/HTML, ссылка; аутентификация SMTP и стабильный Message-ID | SMTP статус; принятие сервером не доказывает доставку в inbox |
| Email gateway | `EMAIL_PROVIDER_MODE=http` и подходящее уведомление | Email получателя, тема, текст/HTML уведомления, ссылка и idempotency key | Статус доставки, безопасный код отказа |
| Push gateway | `PUSH_PROVIDER_MODE=http`, зарегистрированное устройство и настройки получателя | Расшифрованный push token, заголовок, текст, ссылка и idempotency key | Статус доставки |
| Calendar gateway / OAuth provider | Настроенная интеграция и явное подключение пользователя | OAuth code/state/PKCE в соответствующей фазе, access token для вызова; данные события: название, ссылка встречи, время, версия, при наличии attendees | Access/refresh tokens, внешний event ID и состояние синхронизации |
| TURN | Клиенту требуется релей или включён forced relay | Сетевые адреса, краткоживущие TURN credentials и релейный WebRTC-трафик | Передача пакетов между клиентом и SFU |

Generic gateways являются реализованной границей интеграции, а не гарантией
совместимости с любым API Google, Microsoft, почтового сервиса. Внешний
gateway должен соблюдать идемпотентность и контракт версии календарного события.
Повторы доставки ограничены, но имеют семантику at-least-once.

Клиентская телеметрия не использует внешний SDK и отправляется только на тот же
origin приложения; последующая отправка серверных логов внешнему операторскому
коллектору должна быть учтена в конфигурации самой организации.

## Хранение, удаление и резервные копии

Файлы записей хранятся 7 суток после завершения обработки (`ended_at`), затем
автоматически удаляются из S3-хранилища. API запускает очистку при старте и раз
в минуту. Удаляются видео/аудио, превью, архивы дорожек, сегменты и все поколения
объектов только внутри пространства конкретной записи. Просроченная запись
сразу исключается из списков и чтения; ранее выданные ссылки перестают работать
после физического удаления объекта. Метаданные записи и журнал событий остаются
для аудита с `deleted_at`, без ссылок на файлы. Ошибка хранилища повторяется на
следующем проходе, не блокируя остальные записи. Активные состояния и действующая
аренда recorder исключены из удаления. Для старых завершённых задач без `ended_at`
срок отсчитывается от `stopped_at`, затем `updated_at`/`created_at`.

В приложении нет общего автоматического TTL для аккаунтов, завершённых встреч,
привязанных файлов чата, сообщений и завершённых background jobs.
Отключение feature flag не является удалением уже сохранённых данных. Отзыв
доступа скрывает материал при последующих запросах, но не отзывает байты, уже
скачанные пользователем, и не изменяет старые резервные копии.

Условия очистки spool record-worker определяют
`RECORDING_KEEP_LOCAL`, состояние записи и восстановление финализации: успешная
публикация очищает spool по умолчанию, ошибка сохраняет его. Retention S3 не удаляет
такие локальные каталоги. `RECORDING_MAX_MIB` ограничивает входящий RTP, а не полное
потребление диска промежуточными файлами.

Полное восстановление требует согласованной копии PostgreSQL, объектов S3-хранилища
и необходимых операторских секретов. DB dump без файлов не восстанавливает
записи; файлы без метаданных не восстанавливают права и подтверждённое поколение.
Копирование текущих S3-объектов само по себе не является транзакционным snapshot
базы и bucket. Для согласованной контрольной точки останавливают изменяющие
процессы/приём работ по процедуре резервирования и проверяют восстановление
в изолированной цели. Object backup содержит приватные байты и manifest с
ключами объектов: ограничение файловых прав не заменяет шифрование носителя.

Политику сроков хранения, удаления backup, доступа к журналам, владения ключами
и внешних провайдеров организация фиксирует отдельно. Проверенная процедура
восстановления и её фактические результаты должны сопровождать выпуск:
[DEPLOYMENT.md](DEPLOYMENT.md), [ROLLBACK.md](ROLLBACK.md),
[операционный runbook](operations/README.md).

Схемы: [`database/migrations`](../database/migrations). Контракты интеграций:
[content-integrations.md](content-integrations.md). Настройки по умолчанию:
[`product.go`](../internal/config/product.go).
