# Данные и внешние передачи

Актуализировано 29 октября 2026 года.

Документ описывает данные, которые хранит и передаёт приложение. Он не определяет юридические
основания обработки, сроки хранения организации, согласия участников или
договоры с провайдерами. Эти решения должен отдельно зафиксировать владелец
развёртывания перед включением внешних интеграций.

## Что хранится

| Данные | Где находятся | Доступ и жизненный цикл |
| --- | --- | --- |
| Аккаунт: UUID, email, имя, даты, `is_admin` | PostgreSQL `users` | Серверная авторизация; пароль хранится как хеш Argon2id с солью, исходный пароль не сохраняется |
| Авторизация и предпочтения устройств | Короткий JWT и профиль в `sessionStorage`; секрет сессии в HttpOnly cookie; SHA-256 секрета и отзыв в PostgreSQL; настройки устройств и отметка явного выхода в локальном хранилище браузера | Серверная сессия аккаунта без тайм-аута; выход из аккаунта отзывает её и связанные JWT. Пароль и секрет cookie в JS/логи не передаются; идентификатор устройства не входит в серверную телеметрию |
| Встречи, расписание, участие, допуск, роли, модерация | PostgreSQL | Участие и допуск проверяются при обращении; UUID/ссылка не заменяют проверку прав |
| Соединения и маршруты, билеты, временные права на задачи (leases), ограничения частоты | Redis; сведения о сессиях участников также в PostgreSQL | Redis-данные временные и имеют TTL; Pub/Sub не является устойчивой историей |
| Сообщения, ответы, версии, прочтение | PostgreSQL `chat_messages`, `chat_read_states` | Доступ участникам, допущенным к переписке; удаление очищает текущий текст и оставляет отметку об удалении (tombstone). Старые резервные копии хранятся отдельно |
| Вложения: имя, размер, MIME, контрольная сумма, статус | Метаданные в PostgreSQL; содержимое файлов в приватном S3-хранилище | До 10 МиБ; скачивание после проверки доступа по короткоживущей ссылке; незавершённые вложения очищаются; для привязанных вложений общий срок автоматического удаления не задан |
| Записи, сегменты, статусы, поколения и аренды | PostgreSQL; временный spool на диске recorder; готовые объекты в S3-хранилище | Финальные аудио/видео, превью и архивы выдаются по проверенным метаданным поколения; бакет закрыт от публичного доступа |
| Уведомления, предпочтения, фоновые задания и доставка | PostgreSQL | Личные получатели, ссылки на ресурсы, состояния и безопасные коды ошибок; уведомление не предоставляет права на ресурс |
| Токены OAuth и push-уведомлений | PostgreSQL; данные зашифрованы с помощью AES-GCM | Независимый ключ `PROVIDER_TOKEN_ENCRYPTION_KEY`; клиентские ответы не раскрывают токены; при отзыве доступа зашифрованные токены удаляются из рабочей базы, резервные копии могут их сохранять |
| OAuth state и PKCE verifier | PostgreSQL | Одноразовый state со сроком доступа 10 минут; использованные и просроченные строки удаляются фоновыми задачами ограниченными порциями |
| Диагностика и метрики | stdout/journal контейнеров, Prometheus | Метрики используют ограниченные категории; журналы могут содержать идентификаторы сущностей и IP-адреса соединений в журнале доступа прокси, но не должны содержать тела чата, SDP, JWT и подписанные параметры URL |
| Ошибки веб-клиента | Проверенный JSON в журнале API и агрегированный счётчик Prometheus при включённой телеметрии | Версия, шаблон маршрута, код, семейство браузера, до пяти позиций ошибки в собственных JS-файлах; без исходного сообщения, параметров URL, токенов, содержимого встречи и идентификатора пользователя |

Браузер передаёт медиаданные по WebRTC; TLS защищает публичные HTTP/WSS-запросы.
SFU принимает медиа, а серверная запись имеет доступ к его
содержимому. Сквозное шифрование (end-to-end encryption), при котором сервер
не может прочитать содержимое, не заявляется.

## Внутренние маршруты медиа и команд

Браузер отправляет Opus/VP8 по WebRTC напрямую в SFU либо через Coturn.
API передаёт SDP/ICE и команды по WS/защищённому HTTP; RTP через API и RabbitMQ
не проходит. SFU передаёт record-worker защищённый HTTP NDJSON
поток: метаданные и RTP в поле JSON `rtp` (base64). SFU не декодирует эти пакеты.
Обработчик записи извлекает медиаданные из пакетов и сохраняет их в IVF/Ogg в локальном каталоге `/storage/records/{recordId}`,
FFmpeg создаёт сегменты и итоговый файл записи.

`recording_outbox` и запись создаются в одной PostgreSQL-транзакции. RabbitMQ
доставляет `record.start`/`record.stop`, Redis — временные события для WS/SSE,
`background_jobs` — фоновые задания, сохраняемые в базе. Это разные каналы с разной
устойчивостью; подтверждение RabbitMQ не означает готовность медиафайла.

Сервис Compose `minio` может быть классическим MinIO либо SeaweedFS из защищённого варианта установщика (hardened). Оба предоставляют S3 API с закрытым доступом; `MINIO_*` — имя совместимой
конфигурации. Локальный spool recorder не является S3-томом и требует отдельного
контроля свободного места и очистки. Состав поставки: [ARCHITECTURE.md](ARCHITECTURE.md).

## Какие данные могут покинуть развёртывание

По умолчанию внешние адаптеры имеют режим `noop`. `mock` разрешён только в локальном или тестовом окружении и выдаёт помеченные
демонстрационные результаты. Адреса сервисов и секреты задаёт оператор;
пользователь не передаёт произвольный адрес сервиса для серверного запроса.

| Получатель | Условие | Передаваемые данные | Обратные данные |
| --- | --- | --- | --- |
| SMTP-сервер | `EMAIL_PROVIDER_MODE=smtp` и подходящее письмо | Адрес получателя, тема, текст/HTML, ссылка; аутентификация SMTP и стабильный Message-ID | Статус SMTP; принятие письма сервером не подтверждает попадание в папку «Входящие» |
| Почтовый шлюз | `EMAIL_PROVIDER_MODE=http` и подходящее уведомление | Email получателя, тема, текст/HTML уведомления, ссылка и ключ идемпотентности | Статус доставки, безопасный код отказа |
| Шлюз push-уведомлений | `PUSH_PROVIDER_MODE=http`, зарегистрированное устройство и настройки получателя | Расшифрованный токен push-уведомлений, заголовок, текст, ссылка и ключ идемпотентности | Статус доставки |
| Календарный шлюз / провайдер OAuth | Настроенная интеграция и явное подключение пользователя | OAuth code/state/PKCE в соответствующей фазе, access token для вызова; данные события: название, ссылка встречи, время, версия, при наличии — список участников (attendees) | Токены доступа и обновления, внешний идентификатор события и состояние синхронизации |
| TURN | Клиенту нужна ретрансляция или включён принудительный режим forced relay | Сетевые адреса, краткоживущие учётные данные TURN и ретранслируемый WebRTC-трафик | Передача пакетов между клиентом и SFU |

Универсальные шлюзы (generic gateways) задают контракт интеграции, но не гарантируют
совместимость с любым API Google, Microsoft или почтового сервиса. Внешний
шлюз должен поддерживать идемпотентность и соблюдать правила версионирования календарных событий.
Число повторных попыток доставки ограничено. Используется модель at-least-once:
одна операция может быть доставлена повторно.

Клиентская телеметрия не использует внешний SDK и отправляется только на тот же
origin приложения; последующая отправка серверных журналов внешнему операторскому
коллектору должна быть учтена в конфигурации самой организации.

## Хранение, удаление и резервные копии

Файлы записей хранятся 7 суток после завершения обработки (`ended_at`), затем
автоматически удаляются из S3-хранилища. API запускает очистку при старте и раз
в минуту. Удаляются видео/аудио, превью, архивы дорожек, сегменты и все поколения
объектов только внутри пространства конкретной записи. Просроченная запись
сразу исключается из списков и чтения; ранее выданные ссылки перестают работать
после физического удаления объекта. Метаданные записи и журнал событий остаются
для аудита с `deleted_at`, без ссылок на файлы. Ошибка хранилища повторяется на
следующем проходе, не блокируя остальные записи. Активные состояния и действующая
аренда recorder исключены из удаления. Для старых завершённых задач без `ended_at`
срок отсчитывается от `stopped_at`, затем `updated_at`/`created_at`.

В приложении нет общего автоматического TTL для аккаунтов, завершённых встреч,
привязанных файлов чата, сообщений и завершённых фоновых заданий.
Отключение возможности через feature flag не является удалением уже сохранённых данных. Отзыв
доступа скрывает материал при последующих запросах, но не удаляет файлы, уже
скачанные пользователем, и не изменяет старые резервные копии.

Условия очистки spool record-worker определяют
`RECORDING_KEEP_LOCAL`, состояние записи и восстановление финализации: успешная
публикация очищает spool по умолчанию, ошибка сохраняет его. Очистка S3 по сроку хранения не удаляет
такие локальные каталоги. `RECORDING_MAX_MIB` ограничивает входящий RTP, а не полное
потребление диска промежуточными файлами.

Полное восстановление требует согласованной копии PostgreSQL, объектов S3-хранилища
и необходимых операторских секретов. Дамп базы данных без файлов не восстанавливает
записи; файлы без метаданных не восстанавливают права и подтверждённое поколение.
Копирование текущих S3-объектов само по себе не является согласованным снимком
базы и бакета. Для согласованной контрольной точки останавливают изменяющие
процессы/приём работ по процедуре резервирования и проверяют восстановление
в изолированном окружении. Резервная копия объектов содержит приватные файлы и манифест с
ключами объектов: ограничение файловых прав не заменяет шифрование носителя.

Политику сроков хранения, удаления резервных копий, доступа к журналам, владения ключами
и внешних провайдеров организация фиксирует отдельно. Проверенная процедура
восстановления и её фактические результаты должны сопровождать выпуск:
[DEPLOYMENT.md](DEPLOYMENT.md), [ROLLBACK.md](ROLLBACK.md),
[инструкции по эксплуатации](operations/README.md).

Схемы: [`database/migrations`](../database/migrations). Контракты интеграций:
[content-integrations.md](content-integrations.md). Настройки по умолчанию:
[`product.go`](../internal/config/product.go).
