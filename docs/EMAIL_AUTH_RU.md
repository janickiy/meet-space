# Подтверждение email и восстановление пароля

## Настройка доставки

Во вкладке «Почта» административных настроек заполните SMTP-сервер, порт,
логин, пароль, отправителя и шифрование TLS или STARTTLS. Включите доставку
через SMTP и сохраните группу. Пустое поле пароля при следующем сохранении
сохраняет уже заданный секрет; значение пароля API не возвращает.

«Подтверждение email» находится во вкладке «Основные». Переключатель доступен
для изменения только после сохранения включённого и полностью настроенного
SMTP. Черновик во вкладке «Почта» не открывает редактирование. API проверяет
сохранённые параметры и доступность зашифрованного пароля; перед включением
подтверждения также требуется ключ шифрования токенов. Сначала выключите
подтверждение email, если требуется отключить SMTP.

API и product worker должны использовать один постоянный
`PROVIDER_TOKEN_ENCRYPTION_KEY`. Он защищает пароль SMTP и одноразовые токены;
замена ключа без переноса секретов нарушит доставку ожидающих писем.
`PUBLIC_FRONTEND_URL` задаёт доверенный публичный адрес установки: HTTP/HTTPS
origin без логина, пути, query и fragment. Адреса ссылок берутся из этой
конфигурации, а не из входящего Host или пользовательского запроса.
На рабочих хостах используйте HTTPS и рабочий сертификат SMTP-сервера.

6 ноября 2026 по запросу владельца SMTP-параметры скопированы с
`meeting.janickiy.com` на `chat.stage.org.ru` через административный API.
Пароль сохранён с использованием собственного ключа шифрования целевой установки;
остальные настройки и политика подтверждения email сохранены.
Обычные обновления приложения не переносят SMTP-параметры между установками.
Проверка доставки пока не завершена: с обоих хостов соединения с
`smtp.timeweb.ru` на портах 465 и 587 завершаются тайм-аутом до авторизации.
Локального запрета исходящих соединений не обнаружено; требуется проверить
внешние сетевые ограничения. SMTP-аутентификация и получение писем не подтверждены.
Наличие сохранённых параметров само по себе не подтверждает доставку во
входящие: проверьте её отдельным письмом в контролируемый почтовый ящик.

## Регистрация и подтверждение

При включённой политике новый пользователь указывает email при регистрации.
Аккаунт создаётся с требованием подтверждения, а письмо ставится в устойчивую
фоновую очередь. Вход и использование защищённых функций недоступны до
подтверждения адреса. Ссылка открывает страницу `/verify-email`, действует
24 часа и используется один раз. Открытие страницы само по себе не меняет
состояние: пользователь подтверждает действие явным POST-запросом.

Существующие аккаунты, созданные без требования подтверждения, сохраняют
доступ после включения политики. Выключение политики разрешает вход ожидающим
подтверждения аккаунтам; повторное включение снова применяет к ним требование.
Восстановление пароля не подтверждает email вместо пользователя.

Повторная отправка одному ожидающему аккаунту доступна не чаще раза в минуту.
Новая ссылка заменяет прежнюю. Для неизвестного, уже подтверждённого или
неподходящего аккаунта повторная отправка не раскрывает его состояние.

## Восстановление пароля

Восстановление доступно при настроенном и включённом SMTP независимо от
переключателя «Подтверждение email». Пользователь выбирает «Забыли пароль?»
на странице входа и указывает email аккаунта. Обычный успешный ответ одинаков
для существующего и неизвестного адреса; письмо ставится в очередь только для
подходящего аккаунта с паролем. Заблокированный аккаунт получает отдельное
сообщение о блокировке, как и при авторизации.

Ссылка открывает `/reset-password`, действует один час и используется один раз.
Токен передаётся во fragment, убирается из адресной строки и остаётся только
в памяти страницы. Пользователь вводит и подтверждает новый пароль длиной
от 8 до 128 символов. Изменение происходит только после отправки формы.
Истёкшая, заменённая или использованная ссылка не меняет пароль.
Повторный запрос одному аккаунту ограничен одной новой ссылкой в минуту.

В одной транзакции сервер меняет hash пароля, использует токен, отзывает
refresh-сессии и прежние bearer/legacy-токены и ставит в очередь уведомление
«Пароль MeetSpace изменён» на email аккаунта. Сокеты текущего экземпляра API
закрываются после успешной транзакции; другие экземпляры проверяют устойчивое
состояние отзыва при авторизации. Автоматического входа после сброса нет:
пользователь входит с новым паролем. Требование подтверждения email и
блокировка аккаунта продолжают действовать.

## HTTP-контракт

Все маршруты ниже имеют префикс `/api/v1/auth`, принимают JSON и проверяют
разрешённый Origin. Ответы не кешируются. Rate limit ограничивает запросы по
IP; исчерпание лимита возвращает 429.

| POST-маршрут | Тело | Результат |
|---|---|---|
| `/verify-email` | `{token}` | 200 после подтверждения; 422 для недействительной или истёкшей ссылки |
| `/verify-email/resend` | `{email}` | 200 с общим сообщением об отправке при подходящем состоянии аккаунта |
| `/password-recovery` | `{email}` | 200 с общим сообщением; 403 для заблокированного аккаунта; 503 при недоступном восстановлении или ненастроенном SMTP |
| `/reset-password` | `{token, password}` | 200 после смены; 422 для недействительной ссылки или пароля; 403 для заблокированного аккаунта |

Некорректный email возвращает 422, неверный JSON или неизвестные поля — 400.
Запросы восстановления и смены пароля, а также повторная отправка подтверждения
ограничены пятью запросами в минуту с IP; подтверждение — двадцатью.
Успешный ответ на запрос письма
означает приём операции, а не фактическое получение письма адресатом.

## Хранение и эксплуатация

Миграция 45 добавляет `password_recoveries`; она не изменяет исторические
миграции. Перед установкой сохраните резервную копию БД и конфигурации,
добавьте новый файл миграции и обновите API, product worker, публичный frontend
и admin proxy. Сохраняйте исходные файлы и контрольные суммы прежних миграций
конкретной установки.

Случайные токены имеют 256 бит энтропии. Для проверки хранится SHA-256 hash,
для фоновой отправки — зашифрованное значение с привязкой к операции.
После использования зашифрованное значение стирается. Очередь хранит IDs
операций; перед отправкой проверяются актуальность операции, допустимость
аккаунта и lease задания. Повторные попытки сохраняют ключ идемпотентности;
SMTP не гарантирует строго однократную доставку сообщения.

Не записывайте в логи токены, ссылки целиком, пароли, SMTP-секреты и тела
запросов восстановления. SQL для репозиториев одноразовых токенов не
логируется; журнал ошибок использует безопасные категории. Диагностируйте
доставку по ID задания, состоянию очереди и безопасному коду ошибки.

Для приёмки проверьте полный цикл регистрации и подтверждения, повторную
отправку, одноразовость и срок ссылок, восстановление, отзыв старых сессий,
блокировку аккаунта и поведение без SMTP. Изолированные браузерные и
PostgreSQL-тесты проверяют приложение и очередь; они не подтверждают
доставку в реальный почтовый ящик. Результаты развёртывания и проверок на
конкретных хостах фиксируются отдельно в [ADMIN_AUDIT_RU.md](ADMIN_AUDIT_RU.md).

Меры защиты сверены с [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).
Сообщение о заблокированном аккаунте оставлено отдельным по требованиям продукта.
