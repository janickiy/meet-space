# Сборка технического руководства MeetSpace

Документ: `MEETSPACE_TECHNICAL_GUIDE_RU.pdf`. Редактируемый источник: `MEETSPACE_TECHNICAL_GUIDE_RU.md`. Предыдущие файлы `MEETSPACE_TECHNICAL_DOCUMENTATION_RU.*` не заменяются.

## Содержимое редакции от 29 октября 2026 года

Девять глав: назначение и структура проекта; архитектура; медиасвязь и запись; API; база данных; установка; обслуживание; границы проверки; поддержка.

Руководство обновлено после удаления распознавания речи и связанных функций. Сервис записи называется `record-worker`. Описаны 170 регистраций HTTP и общих контрактов, включая служебные; 42 таблицы и 435 полей после 37 миграций, включая реестр миграций. Коммит исходников указан на обложке и в разделе 8.1.

Результат проверки оформления: 202 страницы единого альбомного формата A4, 11 схем, 130 переходов оглавления. Проверены все контактные листы, крупные изображения схем, таблиц и команд. Автоматическая проверка не выявила пустых страниц, выхода текста или изображений за поля, отсутствующих символов. Все изображения встроены без изменения исходных пикселей. 53 блока Bash прошли `bash -n`; команды установки из документа не выполнялись.

Проверки приложения описаны в главе 8. Они не заменяют приёмку на целевом сервере. Миграция 37 проверена на локальном PostgreSQL, включая обновление заполненной БД. Ветка с установленным pgvector в этом прогоне не выполнялась.

## Подготовка и сборка

Нужен Python 3.10 или новее, пакеты из `docs/tools/requirements-pdf.txt` и шрифты с кириллицей. На macOS используются Arial/Courier New/Arial Unicode; на Linux — DejaVu Sans/Mono. Для визуальной проверки нужен Poppler (`pdftoppm`).

Из корня проекта:

```bash
python3 -m venv .venv-docs
.venv-docs/bin/pip install -r docs/tools/requirements-pdf.txt
.venv-docs/bin/python docs/tools/build_technical_guide.py
```

Ожидаемый результат: обновлены PDF и отчёт `.render.json`. Рендерер выполняет два прохода для фактических номеров страниц в оглавлении. Заголовки глав выделены жирным, подразделы имеют отступ, номера страниц выровнены справа. Все схемы размещаются на отдельных страницах.

При нестандартном расположении шрифтов используйте `--font-dir /абсолютный/путь/к/шрифтам`. Дату и коммит можно явно задать параметрами `--date`, `--metadata-date` и `--commit`; они должны соответствовать редакции текста.

## Схемы

Три схемы сервисов и схема учётных записей используют редактируемые Graphviz-исходники в `docs/assets/technical-guide/`. Они обновлены под новую архитектуру; сохранены цветовая легенда, цилиндры хранилищ и подписанные связи. Для их пересборки нужны Node.js, `@viz-js/viz` и `sharp`, доступные обычному механизму поиска модулей Node.js:

```bash
node docs/tools/render_guide_diagrams.cjs
```

Семь остальных ER-схем подключаются из `docs/assets/technical-documentation/`. Схемы удалённых речевых таблиц в документ не входят. PDF использует PNG; исходные DOT и SVG позволяют редактировать обновлённые схемы без потери структуры.

## Проверка PDF

```bash
.venv-docs/bin/python docs/tools/check_pdf.py \
  --pdf docs/MEETSPACE_TECHNICAL_GUIDE_RU.pdf \
  --output-dir tmp/pdfs/technical-guide-review \
  --render --contacts
```

Проверьте `qa-report.json`: единый формат страниц, отсутствие пустых страниц, обрезанного текста, ошибок символов и пропавших изображений. Затем просмотрите контактные листы всех страниц и крупные изображения схем, таблиц и команд. Автоматические проверки не заменяют визуальный просмотр.

## Редактирование

Меняйте канонический Markdown, затем пересобирайте PDF. Сохраняйте уникальные якоря и ссылки оглавления. Изображения подключаются относительными путями внутри `docs`. Команды проверяйте по реализации указанного коммита; конфигурация мастера отличается от ручного развёртывания.

Обновление с удалением речи требует резервной копии, остановки прикладных служб и миграции 37. Обратная миграция не восстанавливает удалённые данные. Порядок перехода и ограничения готовых пакетов приведены в разделе 7.12.

Сборка документа не устанавливает приложение, не меняет базу данных и не публикует файлы на сервере.
