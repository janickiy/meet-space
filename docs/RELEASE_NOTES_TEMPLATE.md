# Шаблон описания выпуска

Скопируйте шаблон в отдельный документ выпуска. Не заменяйте «не проверено» на
«пройдено» без подтверждающих результатов. Для каждой пропущенной проверки укажите
причину, риск и ответственного. Не включайте секреты, JWT, реальные тексты встреч
и подписанные URL.

## Идентификаторы

| Поле | Значение |
| --- | --- |
| Версия | `vX.Y.Z` |
| Полный SHA коммита | Не заполнено |
| Время сборки UTC / SHA-256 исходников | Не заполнено |
| Манифест выпуска / SHA-256 | Не заполнено |
| Дайджесты образов в реестре либо ID образов в архиве / SBOM / отчёты проверки уязвимостей | Ссылки на файлы выпуска |
| Топология / дополнительные файлы Compose / реализация S3 | Отдельный сервер через мастер, classic или shared-host; MinIO либо SeaweedFS |
| Наличие незакоммиченных изменений исходников | Должно быть `false` для реестра образов, проверочного стенда и рабочего окружения |
| Предыдущий манифест | Не заполнено |
| Ответственные / окно обслуживания | Не заполнено |

## Пользовательские изменения

- Добавлено: опишите фактическое поведение без внутренних названий этапов.
- Исправлено: укажите видимый пользователю результат.
- Изменено или удалено: укажите совместимость и необходимые действия пользователя.
- Известные ограничения: перечислите браузеры, сети, провайдеров и сценарии, которые не проверены.

## Изменения для администратора

- Конфигурация и флаги функций: новые значения, безопасные значения по умолчанию, использующие их компоненты и необходимость перезапуска.
- Секреты и провайдеры: способ безопасной подготовки и ротации без самих секретных значений.
- Схема БД: имена файлов миграций, контрольные суммы, измеренная продолжительность и блокировки, порядок расширения и последующего удаления старой схемы (Expand/Contract).
- Данные: заполнение существующих записей, сроки хранения и удаления, изменения формата объектов или содержимого.
- Зависимости: обновления дайджестов образов, Go и npm; отдельное окно обслуживания при необходимости.
- Ресурсы: среда, сценарий, число операций, продолжительность и ограничения измерений.

| --- | --- | --- |
| Go: gofmt / vet / staticcheck / сборка | Не проверено | |
| Интерфейс: стиль / типы / сборка; ручная проверка CSP | Не проверено | |
| Chromium / Firefox / ручная проверка доступности | Не проверено | |
| Проверка зависимостей и образов / SBOM | Не проверено | |
| Локальная репетиция с неизменяемым пакетом | Не проверено | Не заменяет отдельный проверочный стенд |

| Медиа / принудительное использование TURN / TURNS / запись / превью | Не проверено | |
| Резервная копия / изолированная проверка восстановления / связи данных приложения | Не проверено | |
| Откат приложения на текущей схеме | Не проверено | |
| Базовая проверка рабочего окружения / период наблюдения | Не проверено | |

Для дополнительных средств проверки укажите версии, сценарии и результаты.

## План запуска и отката

1. Выбранный неизменяемый манифест, целевое окружение, проект и разрешённые команды.
2. Приостановка изменения данных, резервная копия, миграция и развёртывание; список получателей уведомления об обслуживании.
3. Пилотный запуск и флаги: глобальный набор для развёртывания либо отдельный
   изолированный стенд. Не указывайте выбор групп пользователей, которого нет в приложении.
4. Наблюдение: период, фактическое число запросов, SLI и согласованные условия остановки.
5. Предыдущий манифест и подтверждение совместимости старого кода с новой БД и конфигурацией.
6. При невозможности отката: согласованный план выпуска исправленной версии
   или аварийного восстановления, точка восстановления данных, допустимые потери
   и ответственный. Автоматический откат схемы БД запрещён.

## Решение

решение, ссылки на результаты проверок, исключения и срок их действия. Отдельно
перечислите неподтверждённые сведения. Структура машиночитаемого разрешения —
