# Лендинг MeetSpace — итог реализации

> Исторический отчёт: отражает состояние проекта на дату проверки. После удаления распознавания речи и переименования сервиса записи его перечень компонентов не является описанием текущей версии. Актуальные сведения: [архитектура](ARCHITECTURE.md).

Обновлено: 19 октября 2026. Исходный снимок серверного проекта: `893566bb90f07bdcec4542eec5e00116c423e852`.
Рабочая папка была пустой, поэтому в неё клонирован указанный публичный репозиторий. Изменён существующий веб-клиент на React/TypeScript; отдельного приложения и новых зависимостей нет. Изменения локальные, без публикации и запуска серверного развёртывания.

## Что сделано

Лендинг заново оформлен в светлом продуктовом стиле: белые поверхности, синие и фиолетовые акценты, крупная типографика и интерактивные примеры интерфейса. Структура и содержание адаптированы из `CODEX_PROMPT_MEETSPACE_WEBSITE_CONTENT.md`. По новому указанию пользователя публичный сайт переведён на русский через https://translate.yandex.ru. Переведены тексты, навигация, примеры интерфейса, подписи доступности, страницы приложений и установки, SEO-метаданные. Машинный перевод вычитан в контексте; названия технологий, URL, архитектуры, форматы пакетов и исполняемые команды сохранены.

На главной представлены главный экран с двумя кнопками действия, семь карточек возможностей, отдельные разделы видеовстреч, мессенджера, папок и размещения на своём сервере, три шага установки, Android/Windows/Linux/Web, пять аудиторий, 15 FAQ и заключительный призыв к действию. Основные тексты вынесены в `frontend/src/landing/content.ts`; описания семи возможностей имеют длину 185–203 символа. Возможности и FAQ остаются секциями главной без дублирующих маршрутов.

Иллюстрации продукта явно обозначены как концепция с демонстрационными данными. Использован существующий локальный WebP из репозитория; никаких отзывов, клиентов, цифр популярности и гарантий не выдумано. Мобильная навигация — выдвижная модальная панель с управлением с клавиатуры, Escape и возвратом фокуса. Вкладки поддерживают стрелки/Home/End и описание для скринридера. Учитывается настройка уменьшения анимации; стили публичных страниц изолированы от темы кабинета.

## Маршруты и интеграция

- `/` — новый лендинг для гостя, прежний кабинет для авторизованного пользователя.
- `/welcome` — публичный лендинг независимо от сессии.
- `/download` — отдельная страница Web/Android/Windows/Linux с выбором установщика, инструкциями установки и четырьмя вопросами о приложениях.
- `/self-hosted` — обзор самостоятельного размещения, контроля инфраструктуры и данных, три шага установки и переход к подробному руководству.
- `/docs/self-hosted` — публичная инструкция с оглавлением, копированием команд, диагностикой неполадок и закреплёнными ссылками на исходники.
- `/login`, `/register` и существующие маршруты кабинета сохранены.
- Все четыре публичных маршрута кроме `/` открываются без восстановления авторизации. Основная страница для гостей не скрывается за ошибкой подключения к серверной части.

UI: `Landing`, общие `LandingHeader`/`LandingFooter`, `LandingBrand`, `LandingScene`, `DownloadSection`, `SelfHostedSection`, `InstallSection`, `DownloadPage`, `SelfHostedOverview`, `SelfHostedPage`, `Command`, `PublicPage`, `PublicMetadata`. Страницы в `MarketingPages.tsx` используют общий каркас и самостоятельный H1. Компоненты описывают интерфейс и локальные взаимодействия, не запускают встречи или команды развёртывания из демонстрационных блоков.

## Загрузки

`frontend/src/landing/downloads.ts` — единый типизированный источник проверенных файлов. Карточки показывают версию, архитектуру, формат, размер и опубликованный SHA-256. Добавлены ссылки на предоставленные владельцем [desktop](https://github.com/janickiy/meet-space-win) и [Android](https://github.com/janickiy/meet-space-android) репозитории, а также прямые ссылки на установщики, закреплённые на проверенных коммитах.

- Android: один Universal APK `0.3.7-beta`, Android 8.0+.
- Windows: два EXE `0.1.1-beta`, выбор x64/ARM64.
- Linux: шесть файлов `0.1.1-beta`, выбор x64/ARM64 и AppImage/DEB/RPM.

Все 9 ссылок проверены HTTP Range-запросами: получены реальные двоичные данные ожидаемого формата и размеры, совпадающие с метаданными. Настольный клиент обозначен как тестовая бета-версия без цифровой подписи; Android — как бета-версия APK. SHA-256 взяты из опубликованных метаданных; полные файлы повторно не хешировались и не устанавливались. Пустой список вложений GitHub Releases не означает отсутствие файлов: клиентские проекты публикуют их в каталогах репозитория. Версия серверного выпуска не подставляется вместо версии клиента. Подробности и коммиты — в [аудите загрузок](landing-release-audit.md).

Веб-версия выделена отдельной карточкой. На `/download` дополнительно показаны инструкции установки по платформам, требования и оговорки совместимости, а также четыре FAQ. Неподтверждённые версии Windows и дистрибутивы Linux не объявлены поддерживаемыми только на основании наличия пакета.

## Размещение на своём сервере

Обзор `/self-hosted` объясняет управление инфраструктурой, собственным доменом, размещением данных и обновлениями; ведёт к `/docs/self-hosted`. Подробная инструкция охватывает SSH и ключи, требования, домен/TLS, порты WebRTC/TURN, Docker, закреплённый коммит, фактические файлы окружения и подготовленный манифест выпуска, проверку, миграции, запуск отдельного стенда, подключение, резервное копирование, восстановление и откат. Различает classic и hardened/shared-host конфигурации. Не советует запускать Compose для разработки на публичном VPS; не обещает готовность к рабочей эксплуатации или автоматический TLS по IP. Нет реальных паролей или токенов.

## SEO и сборка

SSG формирует полный русский HTML пяти публичных страниц: `lang="ru"`, отдельные title/description и canonical, Open Graph с `ru_RU`, структурированные данные с `inLanguage: "ru"`, sitemap и robots. Типы данных: `WebApplication` для главной, `CollectionPage` для загрузок, `WebPage` для обзора self-hosted, `TechArticle` для инструкции. Sitemap содержит четыре уникальных URL; `/welcome` имеет canonical на `/`. Нейтральный `app.html` для приватных маршрутов содержит noindex. При SPA-навигации язык документа соответствует публичной или приватной ветке. Nginx и Vite preview выдают новые страницы с завершающим `/` и без него, сохраняя выдачу оболочки SPA для приватных маршрутов. Корневой `/` использует createRoot, чтобы сохранённая сессия не конфликтовала с HTML лендинга.

Домен по умолчанию — подтверждённый `https://meeting.janickiy.com`; для другого домена задайте `VITE_PUBLIC_SITE_URL` при сборке или Docker build-arg `PUBLIC_SITE_URL`. Подробно: [SEO и размещение](landing-seo.md).

## Запуск

Нужен Node, соответствующий `frontend/package.json` (проверено на Node 24.19.0; системный Node 23 не входит в поддерживаемый диапазон).

```sh
cd frontend
npm ci
npm run dev -- --port 5178
```

Откройте `http://127.0.0.1:5178/welcome`. Для проверки готового HTML:

```sh
npm run build
node scripts/check-public-build.mjs
npm run preview -- --port 4183
```

На момент проверки готовый лендинг был доступен на `http://127.0.0.1:4183/welcome`; сервер предварительного просмотра оставлен работающим по просьбе пользователя. Обновлённый сайт открыт и визуально проверен в отдельном окне Chrome. Вход и регистрация используют существующую серверную часть. Локальный предварительный просмотр сам по себе не запускает API, БД или медиасерверы.

## Что проверено

- Успешный `npm run build` новой версии: TypeScript, Vite client, SSR и prerender пяти страниц.

- Во встроенном браузере проверены семь карточек возможностей и все 15 FAQ главной.
- Ширины 360, 390, 750, 768, 1024, 1280, 1440 и 1920: горизонтального переполнения документа нет.
- Все три вкладки демо, включая клавиатуру; меню через Escape с возвратом фокуса и закрытие по логотипу.
- Выбор всех девяти установщиков даёт соответствующие URL из манифеста: Android Universal, Windows x64/ARM64 и шесть сочетаний архитектуры и формата пакета Linux.

Прямые HTTP GET подтвердили пять публичных страниц и варианты с завершающим `/`, приватную оболочку приложения `/login`, `/meetings/new`, `/personal`, а также robots/sitemap; результаты — `product-routes.json`. ## Границы проверки

Не выполнялись установка клиентских пакетов, реальная авторизация/создание аккаунтов, сценарии конференций с серверной частью, полная регрессия кабинета, полные проверки в отдельных Safari/Firefox/Edge/Chrome, автоматический аудит WCAG или измерение полевых Core Web Vitals. Браузерная проверка выполнена во встроенном браузере, а не во всех заявленных браузерах. Образ Docker не собирался, Nginx не запускался; правила сверены статически и воспроизведены в Vite preview. Удалённая установка, нагрузка, TURN и восстановление рабочей установки не проверялись. Код Go/Pion и цепочка обработки медиа не изменены.
