# Продуктовый чеклист выпуска MeetSpace

Отмечайте пункты после проверки конкретной сборки и окружения. Сохраните дату,
коммит, дайджест образа, имя исполнителя и ссылку на результаты. Текущие экраны описаны в [руководстве frontend](../FRONTEND_GUIDE.md)
и [руководстве пользователя](../USER_GUIDE.md),
административное право — в [инструкции администратора](admin.md), базовая эксплуатация — в
[инструкции по эксплуатации](README.md).

| Поле релиза | Значение перед выпуском |
| --- | --- |
| Коммит и дайджесты образов API/media/record-worker/product/frontend/proxy | Заполнить |
| Окружение, публичный адрес HTTPS, дата и ответственный | Заполнить |
| Версия схемы и время согласованной копии PostgreSQL и S3 | Заполнить |
| Конфигурация служб и реализация S3 | Отдельная установка через мастер/classic/shared-host; MinIO/SeaweedFS |
| Результат проверки браузеров, TURN и восстановления | Заполнить ссылками на протоколы |
| Решение о запуске или его отмене и согласованный откат | Заполнить |

## 1. Проверка исходников и сборки

- [ ] Зафиксировать коммит и дайджест каждого образа. Перед сборкой API задать
  `BUILD_VERSION` как неизменяемый идентификатор выпуска или сокращённый SHA коммита и сверить
  встроенный `buildVersion` через авторизованный `GET /api/v1/capabilities`.
  Значение `dev` означает, что версия релиза не была передана при сборке.
- [ ] Выполнить `go build ./...`, `go vet ./...`, staticcheck и govulncheck
  согласно [CI и процессу выпуска](../RELEASE_PROCESS.md). Записать реальные
  результаты.
- [ ] В `frontend/` выполнить `npm ci`, `npm run lint`,
  `npm run typecheck`, `npm run build`, `npm audit --audit-level=high`.
  `npm run lint` проверяет стиль через Prettier; проверка типов TypeScript —
  отдельная обязательная проверка. Фактическую CSP проверить в прокси и браузере без ослабления политики.
- [ ] Вручную пройти критические маршруты с реальными API/PostgreSQL, SFU,
  recorder и согласованными провайдерами. Использовать разрешённые существующие
  аккаунты; новые встречи/записи создавать только с отдельного согласия.
  Сохранить результаты и снимки с очищенными персональными данными.
- [ ] Вручную проверить WebSocket, повторное подключение, аудио и видео через SFU,
  демонстрацию экрана, ретрансляцию TURN, зал ожидания, модерацию, чат, файлы,
  запись, подписанные ссылки и поиск названий встреч.

## 2. Конфигурация, миграция и развёртывание

- [ ] До обновления ограничить новые записи/изменения, дождаться обработки
  активных записей и фоновых заданий. Создать **согласованную** резервную копию PostgreSQL и текущих объектов S3
  с ContentType, а также защищённую копию конфигурации и ключей. История версий
  объектов, произвольные метаданные, RabbitMQ и рабочий каталог записи не входят
  в стандартную процедуру. Проверить чтение копии и восстановление в отдельном
  окружении; измерить достижимые RPO/RTO.
- [ ] Сравнить `.env.production` с `.env.production.example`. Проверить
  независимые непустые ключи JWT, медиа, внутреннего управления, TURN, метрик
  и шифрования провайдеров, пароли, адреса HTTPS, `WS_ALLOWED_ORIGINS`, `HTTP_TRUSTED_PROXIES`,
  `MINIO_PUBLIC_ENDPOINT`, `BUILD_VERSION`, пути сертификатов, `MEDIA_NAT_IPS`, публичный IP TURN,
  порты и доступность диска сервиса записи. Не публиковать вывод env/Compose с секретами.
- [ ] Выбрать полный Compose-контекст по
  [типу установки](../DEPLOYMENT.md#выбор-процедуры-по-типу-установки).
  Выполнить `compose --profile observability --profile migration config --quiet`
  в этом контексте; для общего процесса выпуска — `release.sh validate`. Не печатать
  полную конфигурацию с секретами и не подменять контекст мастера общим скриптом.

- [ ] Проверить миграции на копии схемы с сопоставимым объёмом данных.
  `000021_admin_capability.up.sql` добавляет `users.is_admin BOOLEAN NOT NULL
  DEFAULT FALSE` и три обычных `CREATE INDEX`; регистрация не даёт это право.
  Индексы создаются в общей транзакции явного мигратора; рабочее окружение запускается
  с `AUTO_MIGRATE=false`. Применяется журнал контрольных сумм миграций. На больших
  таблицах возможны задержки и блокировки записей: измерить время на
  копии и согласовать окно обновления. Для `000021` нет down-скрипта: откат
  образа не должен автоматически удалять колонку/данные. Если более старый
  бинарник несовместим со схемой, использовать согласованный снимок PostgreSQL и S3.
- [ ] Для `000022_remove_raised_hands` подготовить резервную копию и окно обслуживания.
  Остановить старый API перед удалением колонок, затем запустить новую версию.
  Down-скрипт возвращает структуру, но не исторические значения счётчиков;
  подробности и порядок отката — в [процессе релиза](../RELEASE_PROCESS.md).
- [ ] Развернуть заранее проверенные неизменяемые образы с контролем миграций,
  завершения активной работы и готовности служб. Использовать [процедуру для выбранной топологии](../DEPLOYMENT.md),
  сохранить ID инфраструктурных образов, тома и точки подключения. `up --build` и
  продолжение через `wizard.py --resume` не являются процедурой обновления работающей установки.
- [ ] Проверить `users.is_admin=false` у новых пользователей. Право назначать
  только по проверенному UUID в доверенной SQL-сессии с отдельным аудитом выдачи;
  owner/co-host конференции не получает глобальный доступ автоматически.

## 3. Возможности и интеграции

- [ ] Проверить необратимый переход [миграции 000037](speech-removal-upgrade.md):
  резервную копию, остановку старых приложений и отсутствие старых контейнеров
  `worker`/`live-worker` среди работающих. После миграции простой откат образов недопустим.
- [ ] Проверить `GET /api/v1/capabilities`: `recordingModes` соответствует
  выпуску; в ответе нет адресов провайдеров, токенов и секретов.
- [ ] Проверить `GET /api/v1/search` по ключевым словам и ограничение доступа.
- [ ] Проверить SMTP, push-уведомления и календарь, если они настроены, включая ограниченные
  повторы и отсутствие реальных отправок в режиме `mock`.
- [ ] Проверить доступные `recordingModes` и реальную композицию/аудиофайлы на
  целевых кодеках и ресурсных лимитах, а не только появление пункта в интерфейсе.

## 4. Готовность, безопасность и сводка состояния

- [ ] Проверить `/health/live` и `/health/ready` внутри доверенной сети для
  API, media-worker и recorder; отдельно проверить состояние product-worker,
  PostgreSQL, Redis, RabbitMQ, S3, свободный диск и отсутствие накопленной очереди RabbitMQ.
  Публичный прокси рабочего окружения должен закрывать `/health`, `/metrics`, `/internal`,
  `/debug`.
- [ ] Проверить HTTPS/WSS, сертификаты, API того же источника (same-origin), CSP без
  `unsafe-eval`/`unsafe-inline`, `nosniff` и `Referrer-Policy: no-referrer`.
  Для внешнего HTTPS `MINIO_PUBLIC_ENDPOINT` убедиться, что в `img-src` и
  `media-src` добавлен только его точный источник; `connect-src` должен содержать
  только явно заданный источник WSS и не зависеть от заголовка Host.
  Убедиться, что журналы доступа и ошибок не сохраняют JWT, OAuth code/state, SDP,
  подписанные URL записи, тексты чата или секреты провайдеров.
- [ ] Обычный JWT: `GET /api/v1/admin/summary` возвращает `403`; без JWT —
  `401`. С JWT явно назначенного администратора маршрут возвращает только агрегаты,
  готовность и ограниченные типы и коды ошибок. После отзыва `is_admin` уже
  выданный JWT должен сразу получать `403`. Страница `/admin` также скрывает
  данные после серверного отказа; получение SPA HTML `200` само по себе не
  проверяет авторизацию.
- [ ] Проверить мониторинг: `/metrics` доступен только с отдельным секретом Bearer,
  Prometheus в закрытой сети (Grafana только classic), уведомление о сбое API/media/recorder,
  рост очереди и диска. Убедиться, что Alertmanager/доставка оповещений реально
  настроены; начальная панель мониторинга без доставки не подтверждает выполнение этого пункта.

## 5. Сквозная проверка пользовательского пути

- [ ] Согласованными обычными аккаунтами проверить вход, обновление токена доступа
  через постоянную сессию, выход, переключение/добавление аккаунта и удаление
  аккаунта на специально выделенных данных. Истечение токена доступа не должно
  само по себе завершать авторизацию пользователя с действующей сессией.
- [ ] Создать немедленную и запланированную встречу, включить зал ожидания,
  скопировать приглашение. У второго пользователя проверить предварительное подключение: превью,
  микрофон и камеру, уровень сигнала, выбор выхода при поддержке браузером,
  запрет доступа, отсутствие и смену устройства, резервный вариант.
  После входа дорожка предварительного просмотра должна остановиться.
- [ ] Проверить ожидание B, допуск A и отсутствие публикации медиа до допуска.
  Затем двусторонний звук и видео, выключение микрофона и камеры, демонстрацию экрана
  и её остановку средствами браузера, модерацию и отключение, реакции, чат и файл.
- [ ] Проверить запуск/остановку записи с видимым индикатором у обоих, обработку/готовый файл. Симулировать
  потерю WS/media-worker и проверить восстановление снимка состояния и явное повторное
  включение устройств.
- [ ] Завершить встречу: она появляется в `/conferences?view=past`; проверить
  карточку встречи, `/recordings` и `/recordings/:id`, защищённое воспроизведение
  и удаление записи с правильными правами. `/history/*` перенаправляет в
  завершённые встречи, `/search` и `/app/search` — на главную. Отдельного раздела
  глобального поиска в интерфейсе нет; серверный поиск названий доступен через `GET /api/v1/search`.
- [ ] В `/personal` проверить личные/групповые чаты, свежесть сортировки списка,
  новые сообщения внизу переписки, поиск, вложения, отключение уведомлений группы и выход из группы,
  роли и информацию об участниках. Проверить личный звонок, микрофон, камеру и демонстрацию экрана,
  завершение и историю; в личном звонке нет записи. Проверить папки и переходы.
- [ ] Уведомления доступны через колокольчик; сохранённый `/notifications`
  показывает список и отметку прочтения, отдельного пункта в меню нет;
  `/settings` сохраняет имя через `PATCH /api/v1/auth/me` (удаление пробелов по краям, 1–100 символов Unicode), после обновления имя видно без нового JWT, email/роль/пароль не
  меняются. Проверить локальные настройки устройств и календарь только при
  реально настроенной интеграции.

## 6. Браузеры, доступность, сеть и нагрузка

- [ ] Выполнить один и тот же короткий проверочный сценарий отдельно в текущих Chrome,
  Edge и Firefox: вход, предварительное подключение с разрешённой и запрещённой камерой, выбор устройств,
  двустороннюю передачу звука и видео, демонстрацию экрана и её остановку средствами браузера, повторное подключение, запись и
  воспроизведение. Safari проверять отдельно на целевых версиях macOS/iOS и
  только после проверки совместимости Pion, `getUserMedia`, `setSinkId` и
  захвата экрана. Записать версии браузеров и недоступные API; успешный
  Chromium не считать результатом Firefox/Safari.
- [ ] Проверить настольную и мобильную версии в портретной и альбомной ориентации:
  реальные разрешения камеры и микрофона, размеры сенсорных кнопок, безопасные
  области экрана, масштаб текста 200% и режим уменьшения анимации. Проверить, что действия комнаты остаются видимыми без горизонтальной
  прокрутки. Успешная сборка не заменяет этот пункт.
- [ ] Пройти вручную **без мыши**: Tab/Shift+Tab от входа до создания встречи;
  открыть/закрыть модальное окно и мобильное меню клавишей Escape, проверить возврат
  фокуса; выбрать устройства и подключиться; в комнате добраться до микрофона, камеры и демонстрации экрана,
  участников, допуска, чата, записи и выхода; открыть завершённые встречи и
  переключить вкладки Arrow/Home/End; проверить `/settings` и отказ `/admin`
  для обычного пользователя. Ни один диалог или меню не должен удерживать фокус
  после закрытия; активный элемент должен оставаться видимым.
- [ ] Повторить ключевые шаги с экранным диктором, проверить названия кнопок,
  состояния выключенного микрофона, записи и ожидания, чтение ошибок без потока дублирующих объявлений. Выполнить ручную проверку контраста; при использовании
  отдельного доступного axe-инструмента сохранить его ограничения. Эти шаги
  сами по себе не доказывают полное соответствие WCAG 2.1 AA.
- [ ] В двух реальных сетях проверить прямое подключение и принудительную ретрансляцию TURN по
  UDP/TCP, затем TURNS с публичным сертификатом; проверить выбранную ICE пару,
  срок выделения TURN-ресурсов, обновление учётных данных при новом PeerConnection,
  блокировку UDP и повторное подключение. Локальные тесты TURN не подтверждают
  работу в интернете, мобильной или корпоративной сети.
- [ ] Измерить загрузку сборки рабочего окружения, время отклика комнаты при активном чате,
  память/CPU/потерю пакетов на целевой численности участников и длительной
  записи. Зафиксировать исходные показатели целевого окружения для сравнения следующих
  выпусков; методика — [проверка нагрузки](../CAPACITY_BASELINE.md).

## 7. Откат и решение о выпуске

- [ ] Перед выпуском сохранить прежние дайджесты образов, конфигурацию, схему и
  процедуру возврата трафика. Проверить совместимость старых бинарников с
  всеми уже применёнными миграциями на копии БД. Обратные миграции автоматически не запускать.
- [ ] При сбое сначала прекратить включение затронутой функции, завершить
  текущую нагрузку в режиме drain, сохранить диагностические данные без приватного содержимого.
  Для отката образов следовать [инструкции](README.md#backup-restore-и-rollback):
  остановить новую версию, поднять закреплённые прежние образы и проверить
  готовность, регистрацию, вход, существующую встречу и запись.
- [ ] Если схема или данные несовместимы, восстановить согласованный
  снимок PostgreSQL и S3. Явно зафиксировать возможную потерю изменений
  после создания снимка; состояние присутствия и права владения Redis не восстанавливать как постоянные данные.
- [ ] Решение **о выпуске (go)** допускается после фактического выполнения обязательных
  пунктов на целевом окружении или явного принятия оставшихся рисков владельцем
  выпуска. До отдельной проверки помечать как **не подтверждено**: развёртывание
  рабочего окружения, внешний доступ WAN/TURNS, совместимость Firefox/Safari и мобильных браузеров,
  полный сценарий работы с клавиатурой и экранным диктором, восстановление резервной копии,
  реальная доставка оповещений, длительная запись и производительность рабочего окружения.
