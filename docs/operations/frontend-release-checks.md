# Проверки интерфейса перед выпуском

Команды определены в [`frontend/package.json`](../../frontend/package.json)
и [`.gitlab-ci.yml`](../../.gitlab-ci.yml). Поддерживаются Node
`^22.22.2 || ^24.15.0 || >=26.0.0`; CI использует Node 24.

## Сборка

Из корня рабочей копии проекта:

```bash
cd frontend
npm ci
npm run lint
npm run typecheck
npm run build
npm audit --audit-level=high
```

`npm run check` объединяет проверку стиля и сборку; сборка уже выполняет `tsc --noEmit`.
Prettier проверяет стиль, typecheck — типы. Проверки в браузере выполняются отдельно
от сборки. Сохраните коммит, хеш файла фиксации зависимостей, версии Node/npm
и результаты команд.

## Проверка в браузере

- Сверьте `/version` и `/version.json` с манифестом. Проверьте загрузку основных
  и отложенно загружаемых ресурсов, отсутствие ошибок в консоли и соответствие CSP
  фактическим заголовкам ответа.
- Проверьте вход, обновление сессии, выход и переключение аккаунтов.
- Проверьте создание встречи, предварительное подключение, зал ожидания, разрешения устройств,
  микрофон/камеру, демонстрацию экрана, повторное подключение и завершение встречи.
- Проверьте личные и групповые сообщения, поиск в переписке, вложения, папки,
  звонок и историю звонков. Новые сообщения должны появляться внизу переписки.
- Проверьте записи: статусы, воспроизведение, скачивание и права удаления.
- Повторите критические сценарии в целевых браузерах и мобильной вёрстке.
  Проверьте клавиатуру, фокус, диалоговые окна, масштаб текста и экранный диктор.
- Проверьте медиа из другой сети, включая принудительную ретрансляцию через TURN/TURNS.

Подробные шаги и критерии — в [продуктовом чеклисте](RELEASE_CHECKLIST.md).
Фиксируйте версии браузеров, окружение, фактический результат и ограничения.

## Обновление зависимостей

Перед изменением пакета изучите список изменений и совместимость используемых API.
Обновите package.json и файл фиксации зависимостей, выполните сборку, проверку
уязвимостей и затронутые сценарии в браузере. Сравните размеры JS, CSS и шрифтов
с предыдущей сборкой при одинаковых
параметрах, включая флаг `CLIENT_TELEMETRY_ENABLED`.

Перед распространением составьте перечень зависимостей по файлу фиксации версий данного выпуска
и проверьте LICENSE/NOTICE фактически поставляемых JS, CSS, шрифтов и бинарников.
Сведения о версии `latest` в реестре пакетов и наличие поля license не заменяют проверку
совместимости и условий поставки.

Условия выпуска в рабочее окружение — [PRODUCTION_LAUNCH_CHECKLIST.md](../PRODUCTION_LAUNCH_CHECKLIST.md).
