# Проверки frontend перед выпуском

Команды определены в [`frontend/package.json`](../../frontend/package.json)
и [`.gitlab-ci.yml`](../../.gitlab-ci.yml). Поддерживаются Node
`^22.22.2 || ^24.15.0 || >=26.0.0`; CI использует Node 24.

## Сборка

Из корня checkout:

```bash
cd frontend
npm ci
npm run lint
npm run typecheck
npm run build
npm audit --audit-level=high
```

`npm run check` объединяет lint и build; build уже выполняет `tsc --noEmit`.
Prettier проверяет стиль, typecheck — типы. Browser-проверки выполняются отдельно
от сборки. Сохраните commit, hash lockfile, версии Node/npm и результаты команд.

## Проверка в браузере

- Сверьте `/version` и `/version.json` с манифестом. Проверьте загрузку основных
  и lazy assets, отсутствие ошибок в console и соответствие CSP реальным headers.
- Проверьте вход, обновление сессии, выход и переключение аккаунтов.
- Проверьте создание встречи, prejoin, зал ожидания, разрешения устройств,
  микрофон/камеру, демонстрацию экрана, reconnect и завершение встречи.
- Проверьте личные и групповые сообщения, поиск в переписке, вложения, папки,
  звонок и историю звонков. Новые сообщения должны появляться внизу переписки.
- Проверьте записи: статусы, воспроизведение, скачивание и права удаления.
- Повторите критические сценарии в целевых браузерах и мобильной вёрстке.
  Проверьте клавиатуру, фокус, dialogs, масштаб текста и экранный диктор.
- Проверьте медиа из другой сети, включая принудительный relay/TURNS.

Подробные шаги и критерии — в [продуктовом чеклисте](RELEASE_CHECKLIST.md).
Фиксируйте версии браузеров, окружение, фактический результат и ограничения.

## Обновление зависимостей

Для изменения пакета проверьте changelog и совместимость используемых API,
обновите package.json и lockfile, выполните сборку, audit и затронутые browser-
сценарии. Сравнивайте размер JS/CSS/fonts с предыдущей сборкой при одинаковых
параметрах, включая флаг `CLIENT_TELEMETRY_ENABLED`.

Перед распространением составьте инвентаризацию по lockfile данного выпуска
и проверьте LICENSE/NOTICE фактически поставляемых JS, CSS, шрифтов и бинарников.
Сведения registry `latest` и наличие поля license не заменяют проверку
совместимости и условий поставки.

Условия production-выпуска — [PRODUCTION_LAUNCH_CHECKLIST.md](../PRODUCTION_LAUNCH_CHECKLIST.md).
