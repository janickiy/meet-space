# Реализация административной панели MeetSpace

В репозитории добавлены самостоятельная административная SPA, отдельные
административные учётные записи и сессии, Go API, миграции, сборка и установка.
Интерфейс использует согласованный тёмный дизайн с мятным акцентом; доступны
светлая тема и мобильная навигация. Данные поступают из API, демонстрационные
аккаунты и фиктивные показатели в рабочее приложение не включены.

Порядок включения, обновления, восстановления доступа и настройки HTTPS описан
в [ADMIN_DEPLOYMENT_RU.md](ADMIN_DEPLOYMENT_RU.md). Локальная разработка SPA и её
контракт с API — в [admin/README.md](../admin/README.md).

## Выполненный объём

| Область | Реализованное поведение |
|---|---|
| Вход | Логин `username` и пароль, отдельная административная сессия, выход, смена своего пароля. Email необязателен и не используется для входа. |
| Главная | Агрегаты пользователей, конференций, записей и хранилища; состояние сервисов. Нулевые показатели отличаются от отсутствующих. |
| Пользователи | Серверные поиск, фильтры, сортировка и пагинация; блокировка/разблокировка с подтверждением. Пользовательские данные сохраняются. |
| Администраторы | Создание, редактирование, блокировка/разблокировка, удаление, смена/сброс пароля, последний вход. Защита последнего активного администратора, включая конкурентные операции. |
| Конференции | Список, организатор, состояние, участники, даты и запись; только просмотр. |
| Чаты | Обезличенные агрегаты личных/групповых чатов и сообщений; содержимое личных сообщений недоступно. |
| Записи | Список и фильтры, длительность/размер/состояние, подтверждение удаления через существующий механизм. Удаление работающей записи не предлагается. |
| Файлы | Количество и объём по сохранённым метаданным, категории файлов. Общая ёмкость физического хранилища не выдумывается. |
| Система | Проверки API, Media Worker, Record Worker, Product Worker, PostgreSQL, Redis и RabbitMQ; время проверки и доступные диагностические сведения. |
| Настройки | Просмотр фактически действующей конфигурации с маскированием секретов. Изменение параметров из панели пока не поддерживается. |
| Журнал аудита | Серверные поиск, фильтры и пагинация; входы, изменения аккаунтов, блокировки и операции с записями. API редактирования/удаления журнала отсутствует. |

Для интерфейса предусмотрены загрузка, отсутствие данных, ошибки, повтор запроса,
подтверждения опасных действий и возврат ко входу после истечения сессии.
Таблицы передают фильтры на сервер; отменённые запросы используют `AbortSignal`.
Шрифты и иконки входят в локальные assets, внешние CDN не требуются.

## Архитектура и границы доступа

SPA находится в `admin/` и собирается независимо от пользовательского
`frontend/`. Используются React, TypeScript, Vite, React Router и TanStack Query.
Для согласованного интерфейса применены собственные компоненты; Refine,
Ant Design и дополнительные транспортные библиотеки не добавлялись только
ради соответствия рекомендуемому списку из исходного промпта.

Административный HTTP listener Go работает на внутреннем `8082`; порт не
публикуется в Compose. Существующий Nginx proxy обслуживает SPA и HTTPS на
отдельном внешнем порту, по умолчанию `8081`. `ADMIN_HTTPS_PORT` меняет порт хоста,
`ADMIN_PUBLIC_URL` задаёт проверяемый origin. При пустом URL он выводится из
hostname `PUBLIC_FRONTEND_URL` и административного порта. Публичный `443`
возвращает `404` для `/api/v1/admin` и вложенных маршрутов.

`ADMIN_ENABLED=false` отключает Go listener и создание административного
Nginx server. В текущей Compose-конфигурации порт остаётся зарезервированным
Docker, но административный TLS/HTTP-сервер на нём отсутствует. Основное
приложение продолжает работать. В примерах `.env` административная панель
выключена по умолчанию; новая интерактивная установка включает её явно.

Пароли хешируются существующим Argon2id-компонентом. Сервер хранит хеши случайных
идентификаторов административных сессий. Cookie
`__Secure-meetspace_admin_session` имеет `Secure`, `HttpOnly`, `SameSite=Strict`
и отдельный `Path=/api/v1/admin`; изоляция не основывается только на TCP-порту.
Токены и пароли не сохраняются в Local Storage. CSRF-токен хранится в памяти
SPA; мутации требуют точного Origin, JSON и `X-CSRF-Token`. Проверка Origin
распространяется и на вход. Административная cookie не авторизует пользовательские
операции, а пользовательский bearer/session не авторизует админку.

Nginx заменяет IP-заголовки собственными значениями и удаляет неподтверждённые
forwarding-заголовки. Go доверяет им только для настроенных trusted proxies.
Пустой список не доверяет IP-заголовкам: в аудите и лимитировании тогда может
использоваться адрес прокси. Настройка доверенной границы подробно описана
в [инструкции развёртывания](ADMIN_DEPLOYMENT_RU.md#адрес-и-изоляция).

с таблицей пользователей. Инструкция операционного endpoint обновлена
в [operations/admin.md](operations/admin.md).

## Миграции 38 и 39

`000038_administrative_console.up.sql` создаёт:

- `administrators`: нормализованный уникальный логин, хеш пароля, имя,
  необязательный email, состояние и даты;
- `administrator_sessions`: хеши идентификаторов сессий, владелец и срок действия;
- `administrator_audit_log`: неизменяемые события; триггер запрещает
  `UPDATE`, `DELETE` и `TRUNCATE`, удаление аккаунта не изменяет историю;
- `administrator_login_limits`: ограничение попыток входа;
- `users.is_blocked` и `users.auth_invalid_before`: блокировка и граница
  отзыва пользовательской авторизации, а также необходимые индексы.

`000039_administrator_resource_indexes.up.sql` добавляет индексы списков
конференций, неудалённых записей и зарегистрированных пользователей.

Обе миграции имеют `down.sql`. Откат 38 удаляет административные таблицы и новые
признаки пользовательской авторизации: он не является способом безопасного
отката приложения с сохранением аккаунтов и аудита. Для обычного отката версии
следует сохранить расширенную схему и следовать процедуре резервного копирования
и совместимости из инструкции развёртывания. Реальная старая инсталляция в этой
работе не обновлялась и не откатывалась.

## API

Все маршруты ниже находятся под `/api/v1/admin`. Кроме входа, они требуют
административную сессию; мутации дополнительно требуют CSRF и корректный Origin.

| Метод и путь | Назначение |
|---|---|
| `POST /auth/login` | Вход по JSON `username`, `password`; ответ `{administrator, csrfToken}`. |
| `GET /auth/me` | Текущий администратор и CSRF-токен. |
| `POST /auth/logout` | Отзыв текущей сессии и очистка cookie. |
| `POST /auth/password` | Смена своего пароля: `currentPassword`, `password`. |
| `GET /administrators` | Список администраторов. |
| `POST /administrators` | Создание отдельной административной учётной записи. |
| `PATCH /administrators/{id}` | Изменение данных и состояния в допустимых границах. |
| `DELETE /administrators/{id}` | Удаление с проверкой последнего активного администратора. |
| `POST /administrators/{id}/password` | Смена/сброс пароля с проверками прав и отзывом сессий. |
| `GET /users` | Список зарегистрированных пользователей. |
| `PATCH /users/{id}` | Состояние `active` или `blocked`. |
| `GET /dashboard` | Агрегаты главной страницы. |
| `GET /conferences` | Метаданные конференций. |
| `GET /chats` | Только агрегированная статистика чатов. |
| `GET /recordings` | Метаданные записей. |
| `DELETE /recordings/{id}` | Удаление через существующий сервис с проверкой состояния. |
| `GET /files` | Количество/объём и категории по метаданным БД. |
| `GET /system` | Состояние сервисов и доступные метрики. |
| `GET /settings` | Действующая конфигурация без раскрытия секретов. |
| `PATCH /settings` | Зарезервированный контракт: сейчас возвращает `409`, изменение без перезапуска не поддерживается. |
| `GET /audit` | Неизменяемый журнал событий. |

Списки используют `{items, total, page, pageSize}`. Поддерживаемые параметры:
`page`, `pageSize`, `q`, `status`, `sort`, `order`; аудит также использует `action`
и `objectType`. Размер страницы по умолчанию — 20, максимум — 100; запрос поиска
ограничен 200 символами. Для отсутствующей метрики возвращается `null`, а не ноль.

## Проверки и результаты

Проверки выполнялись локально и на изолированном HTTPS-стенде из собранных
Docker-образов с тестовыми аккаунтами и БД. Доступ к production для этих проверок
не требовался.

| Проверка | Результат и границы |
|---|---|
| Go | Полный набор `go test ./...` прошёл. Конфигурация origin, валидация, HTTP/CSRF/cookie boundary и совместимость маршрутов проверяются отдельными тестами. |
| PostgreSQL | Полный `TestAudit` integration suite на одноразовой PostgreSQL с `-race` прошёл: bootstrap, нормализация логинов, отзыв/истечение сессий, append-only аудит, конкурентная защита последнего администратора, блокировка пользователей, ресурсы и безопасное удаление записей. |
| Admin SPA | 12 тестов прошли; TypeScript и production Vite build прошли на поддерживаемом Node.js. Проверены API-клиент, CSRF/cookies, обработка 401, отмена запросов, фильтры и ограничения действий. |
| Пользовательский frontend | Все 39 тестов прошли, включая регрессию переноса прежнего summary endpoint. |
| Браузерный дизайн | Проверены все десять разделов и ширина 320 px; исправлены мобильное меню и шкала графика при нулевой активности. |
| Installer/Compose | 32 теста прошли; два Docker-теста запускаются отдельно. Проверены stdin-передача пароля, сохранение аккаунтов, отказ при ошибках, девять вариантов Compose, нестандартный порт `9443` и отсутствие публикации `8082`. |
| Proxy image | Реальная сборка прошла; оба opt-in Docker-теста прошли на собранном образе: SPA/JavaScript доступны, admin API на публичном порту закрыт, при выключении listener отсутствует. |
| API image | Реальная runtime-сборка прошла; включает API, migrator и `/app/meetspace-admin`. |
| Синтаксис | `bash -n`, `sh -n`, Python compilation и `git diff --check` прошли. |

На настоящем локальном HTTPS-стенде дополнительно подтверждены:

- вход через UI, защищённая cookie и CSRF;
- ответы `200` всех десяти ресурсов панели;
- отсутствие SMTP-секрета в данных API (`null`);
- `404` административного API на публичном HTTPS-порту;
- регистрация и вход обычного пользователя, затем блокировка через админку:
  старый bearer получает `401`; после разблокировки этот bearer остаётся отозванным;
- создание и удаление администратора через UI;
- появление событий `user.block` и `administrator.create` в аудите;
- отсутствие JavaScript-ошибок в проверенном сценарии.

Учёт записей включает сохранённые `record_segment` с `object_key`, исключая
повторный учёт совпадающего `record_file` той же записи и ключа. Dashboard берёт
объём записей из той же категории `FileSummary`. Добавлена регрессия: финальный
файл 1024 байта, сегмент 512 байт и дублирующая ссылка на 1024 байта дают два
объекта и 1536 байт; после удаления объекты записи не входят в сводку.
После этого изменения повторно прошли полный PostgreSQL-прогон с `-race`,
`go test ./...` и сборка API. На финальных API/proxy-образах повторены HTTPS-вход,
dashboard/files, secure cookie и публичный `404`; JavaScript-ошибок не обнаружено.

Для воспроизведения проверок см. команды в
[инструкции развёртывания](ADMIN_DEPLOYMENT_RU.md#проверки-исходников),
[admin/README.md](../admin/README.md#сборка-и-проверка) и
[`scripts/audit-postgres.sh`](../scripts/audit-postgres.sh). PostgreSQL-тесты
требуют отдельной тестовой БД; обычный запуск Go-тестов без неё не заменяет
интеграционный прогон.

## Оставшиеся ограничения

- Настройки доступны только для чтения. Изменение регистрации, SMTP, лимитов,
  политики хранения и STUN/TURN выполняется существующим серверным workflow.
- CPU, RAM, полная ёмкость диска/объектного хранилища и свободное место не измеряются.
  При отсутствии источника показывается «Нет данных». Объёмы файлов — агрегаты
  метаданных, а не результат обхода физического диска.
- Dashboard кешируется на 10 секунд. Административные сессии действуют до
  12 часов, не более 20 на аккаунт; при входе просроченные записи очищаются
  порциями до 500 строк.
- Блокировка не удаляет пользовательские данные. Локальные общие WebSocket
  закрываются сразу; другие реплики обнаруживают блокировку примерно за
  5 секунд, конференционные соединения — при следующем pong, старый SSE —
  примерно за 15 секунд. Медиа завершается через существующую очистку соединений;
  одновременное отключение всех реплик не гарантируется.
- Отдельный сложный RBAC не вводился: активные администраторы имеют одинаковый
  уровень доступа, с ограничениями собственной и последней активной записи.
- Production deployment, проверка обновления реального старого инстанса,
  полная установка на чистом Linux-хосте и восстановление его резервной копии
  **не выполнялись**. Локальные HTTPS-проверки не подтверждают внешнюю доступность,
  реальный сертификат и firewall будущей инсталляции.
