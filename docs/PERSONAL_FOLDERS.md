# Папки личного пространства

## Назначение

Папки помогают пользователю упорядочить доступные ему материалы. Отдельный пункт «Папки» находится в блоке «Личное пространство». В папку можно добавить личный чат, групповой чат и встречу. Встреча и её чат представляют один элемент с `conferences.id`. Записи и файлы не становятся элементами автоматически.

Папка не имеет сообщений, не создаёт новый чат и не предоставляет права доступа. Один элемент может находиться в нескольких папках. Удаление из папки удаляет только связь; удаление папки не удаляет разговоры, встречи или сообщения. Остальные участники не видят названия, порядок и состав чужих папок.

## Интерфейс

- `/folders`: список с доступными счётчиками; создание, переименование, удаление и изменение порядка кнопками вверх/вниз.
- `/folders/:id`: элементы, фильтры «Все», «Встречи», «Чаты», поиск и постраничная загрузка; добавление и удаление связей.
- «Добавить в папку» в меню личного/группового чата и карточки встречи: список папок с независимыми флажками выбора. Создание папки доступно в том же диалоге.
- Карточки переходят в существующий чат или страницу встречи, включая завершённую.
  Отдельного экрана `/history/:id` нет: этот старый адрес ведёт в список завершённых. В папке нет отдельного редактора сообщений или медиасоединения.

Виртуальные фильтры «Все / Личные / Группы / Новые» в сообщениях остаются фильтрами. Они не хранятся в таблице папок. Для управления папками и их выбора используются общие диалоги.

Название содержит 1–50 символов Unicode после удаления пробелов по краям (trim) и нормализации NFC. Управляющие символы, в том числе символы направления текста (bidi), запрещены. Имена одного пользователя не должны совпадать после приведения регистра Unicode (case-fold): «Работа» и «работа» — одно имя. Между пользователями имена независимы. Максимум 100 папок на аккаунт. Порядок папок сохраняется; внутри папки элементы сортируются по активности/дате, без ручного ранжирования.

## Схема и миграция

Миграция `000032_personal_folders`:

| Таблица | Поля и ограничения |
|---|---|
| `folders` | UUID, FK `user_id → users`, name/name_key, position, timestamps; unique owner/name_key и deferrable unique owner/position |
| `folder_conversations` | FK folder и conversation, created_at, составной PK |
| `folder_conferences` | FK folder и conference, created_at, составной PK |

Внешние ключи (FK) исключают ссылки на несуществующие элементы, а ограничения ключей — дубликаты связей. Каскад при удалении папки касается только её связей. Физическое удаление conversation/conference удаляет соответствующие ссылки. Обратные индексы target/folder поддерживают эти операции; owner/position/id поддерживает выдачу списка. Миграция добавляет таблицы и не переносит существующие сообщения. Обратная миграция (down) разрешена только при отсутствии пользовательских папок. Если данные уже есть, требуется совместимое исправление новой миграцией (forward fix).

## Доступ и жизненный цикл

Все операции требуют зарегистрированного аккаунта. Гостевые аккаунты не имеют папок. Чтение, изменение, удаление, изменение порядка и выбор папки доступны только владельцу. Неизвестная и чужая папка возвращают одинаковый `404`.

Разговор видим при текущем `conversation_members.left_at IS NULL`, допустимом
типе direct/group и отсутствии `conversations.deleted_at`; скрытый текущим
пользователем direct (`hidden_at`) также исключается. Персональная граница
очищенной истории применяется к превью. Новое сообщение или явное повторное
открытие direct восстанавливает видимость сохранённых связей без старой истории. Встреча видна допущенным или ожидающим участникам (admitted/waiting), кроме исключённых и отклонённых (kicked/rejected), а также явно покинувших чат конференции. Обычный выход из звонка и приглашённый участник до подключения не равны потере доступа. Ожидающий участник (waiting) получает только базовую карточку без секретов приглашения, имён и числа участников. Число участников возвращается только при наличии доступа к истории.

Доступ проверяется в SQL до сортировки, LIMIT, выборки метаданных и подсчёта элементов. Сохранённая связь с папкой не заменяет проверку участия. Недоступные элементы исключаются из папок, списка кандидатов, флажков выбора и счётчиков. Связь может сохраняться в БД и вновь стать видимой после восстановления доступа. Её можно удалить, даже если текущего доступа к элементу уже нет.

Добавление в папку не подключает пользователя к встрече (join), не отправляет приглашение, не предоставляет допуск (admission) и не меняет роль. Транзакция сначала проверяет принадлежность папки владельцу, затем получает блокировку SHARE целевого элемента и повторно проверяет доступ. После этого она блокирует папку и сохраняет связь. Изменения списка папок одного владельца выполняются последовательно через `users FOR NO KEY UPDATE`, совместимый с блокировками FK key-share. Изменение порядка требует полный текущий набор ID папок пользователя; устаревший набор приводит к конфликту.

## API

Префикс `/api/v1`; Bearer-авторизация, `Cache-Control: private, no-store`, `nosniff`, ограничение частоты. DTO папки: `id`, `name`, `position`, `createdAt`, `updatedAt`, `itemCount`, `conversationCount`, `conferenceCount`, опциональный `contains`.

| Метод | Путь | Данные |
|---|---|---|
| GET | `/folders` | Список до 100 папок; `itemKind` + `itemId` добавляют признак выбора `contains` |
| POST | `/folders` | `{name}` → `{status,item}` |
| GET | `/folders/:id` | `{status,item}` с доступными счётчиками |
| PATCH | `/folders/:id` | `{name}` → `{status,item}` |
| DELETE | `/folders/:id` | Только папка и связи |
| PUT | `/folders/order` | `{ids:[...]}` → `{status,items}` |
| GET | `/folders/:id/items` | `type=all\|conversation\|conference`, `search`, `before`, `limit` |
| PUT / DELETE | `/folders/:id/items/:kind/:itemId` | Идемпотентная связь; kind conversation/conference |
| GET | `/folder-items` | Доступные кандидаты с теми же фильтрами и необязательным `folderId` → `inFolder` |

Страница элементов: `{items:[{type,item,inFolder?}],nextCursor?}`. Для Conversation используется существующий формат personal/group, для Conference — базовая карточка без секретов приглашения. Размер страницы 1–100, по умолчанию 50; `search` после trim — до 100 символов. Курсор связан с аккаунтом, областью, папкой, фильтром, поиском, датой, типом и UUID; между папками/аккаунтами/фильтрами его переносить нельзя. `search` ищет буквальную подстроку с заданными ограничениями: `%` и `_` не превращаются в подстановочные символы SQL.

## Производительность и обновления

Счётчики и метаданные выбираются общими SQL-запросами с проверкой доступа, без отдельного HTTP- или SQL-запроса для каждой строки. Окно выбора получает все папки и их флажки одним ответом. Кандидаты и содержимое папки загружаются страницами по ключу (keyset). Число запросов не растёт вместе с числом элементов на странице.

Общий WebSocket пользователя доставляет только владельцу минимальные события `folder.created`, `folder.updated`, `folder.deleted`, `folder.items.updated` с `folderId` и `folder.reordered` с пустым телом. События публикуются после сохранения данных и помечают кэш как устаревший; актуальные данные по-прежнему загружаются через REST. Другие участники conversation/conference не входят в получателей. Новое WS/media соединение не создаётся.

Ключи React Query включают ID пользователя, а запросы отменяются через AbortSignal. При смене аккаунта диалоги и локальные данные прошлого пользователя сбрасываются. Собственное удаление из группы удаляет известные превью папок и кандидатов из кэша. Отказ `403` при добавлении немедленно удаляет устаревшее превью; подтверждённый сервером ответ `403/404` для недоступной папки очищает её кэш и закрывает диалог. Успешное удаление связи обновляет флажки выбора во всех загруженных страницах кандидатов и убирает карточку только из выбранной папки, даже если последующая повторная загрузка не удался. Повторный запрос REST при получении фокуса и каждые 15 секунд на видимой странице подтверждает доступ для внешних изменений встреч, которые не обязаны публиковать событие изменения папки.

## Ограничения

Поддерживаются только direct, group и conference. Цвет, описание, закрепление, системные папки, перетаскивание (drag/drop) и отдельные записи/файлы не реализованы. Для будущих типов потребуется отдельная модель с настоящими FK и собственными правилами доступа.

Создание возвращает `201 {status,item}`, остальные успешные операции — `200`.
`401` — сессия, `403` — гость/нет доступа к добавляемому элементу, `404` — папка,
`409` — имя, лимит или устаревший полный порядок, `422` — поля/курсор,
`429` — превышение частоты запросов. Список/чтение: 120/мин; создание/переименование/удаление/порядок:
30/мин; добавление/удаление связи: 60/мин, на аккаунт.
