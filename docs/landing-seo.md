# MeetSpace: публичный HTML и SEO

Обновлено 19 октября 2026 по новому заданию `CODEX_PROMPT_MEETSPACE_WEBSITE_CONTENT.md`.
По новому указанию пользователя весь публичный контент переведён на русский
через Яндекс Переводчик (https://translate.yandex.ru), затем вычитан в контексте. Новая версия использует светлое
оформление с синими и фиолетовыми акцентами. Приватные экраны остаются на русском.

## Сборка и маршруты

`frontend/package.json`: `npm run build` выполняет TypeScript-проверку, обычную
сборку Vite и `scripts/prerender-public.mjs`. Скрипт собирает отдельную точку входа Node для SSR `src/entry-public.tsx`, вызывает `renderToString` внутри `MemoryRouter`
и добавляет HTML и метаданные в готовый шаблон Vite.

| URL | Файл в `frontend/dist` | Canonical |
| --- | --- | --- |
| `/` | `index.html` | `/` |
| `/welcome` | `welcome/index.html` | `/` |
| `/download` | `download/index.html` | `/download` |
| `/self-hosted` | `self-hosted/index.html` | `/self-hosted` |
| `/docs/self-hosted` | `docs/self-hosted/index.html` | `/docs/self-hosted` |
| Вход, регистрация и приватные маршруты | `app.html` | Отсутствует |

Пять публичных документов содержат основной текст до выполнения JavaScript.
`/welcome`, `/download`, `/self-hosted` и инструкция гидратируются на клиенте;
они не монтируют провайдеры авторизации, пользовательского оформления или
API-запросов. Переход на `/login` или `/register` включает обычную ветку
приложения. Корневой `/` использует существующий клиентский `createRoot`, чтобы
сохранённая сессия могла показать кабинет без конфликта со статическим лендингом.

`PublicPage` выбирает `Landing`, `DownloadPage`, `SelfHostedOverview` или
`SelfHostedPage`. Обёртки в `MarketingPages.tsx` используют общие шапку и подвал,
ссылку пропуска навигации и `main`; разделы самостоятельных страниц получают
собственный H1. Возможности и общий FAQ остаются секциями главной: отдельные
дублирующие `/features` и `/faq` не создаются. `/welcome` сохранён как публичный
вариант главной независимо от сессии, с canonical на `/`.

Основные русские тексты вынесены в `frontend/src/landing/content.ts`:
главная, семь карточек возможностей, пять аудиторий, три шага установки и
15 вопросов FAQ. Проверенные данные о файлах остаются в `downloads.ts`.

SSR импортирует только публичные компоненты. `lucide-react` включён в сборку SSR,
а React и React DOM остаются внешними зависимостями из той же установки
`node_modules`; новые зависимости не добавлены. Временная папка `.prerender`
удаляется в `finally`, в том числе при ошибке рендеринга. SSR не копирует
публичные картинки во временный каталог.

## Метаданные и свой домен

Общие данные находятся в `frontend/src/landing/metadata.ts`:

- отдельные русские title и description для главной, загрузок,
  обзора самостоятельного размещения и подробной инструкции;
- `lang="ru"` в готовом публичном HTML, `og:locale="ru_RU"` и
  `inLanguage: "ru"` в структурированных данных;
- абсолютные canonical, Open Graph URL и изображение;
- структурированные данные `WebApplication` для главной, `CollectionPage`
  для загрузок, `WebPage` для обзора размещения на своём сервере и `TechArticle` для инструкции,
  без выдуманных цен, отзывов, рейтингов или лицензии;
- `noindex, nofollow`, нейтральное описание и отсутствие публичного canonical
  для входа, регистрации и кабинета.

| Canonical-путь | Title | Длина title / description |
| --- | --- | --- |
| `/` | Скачать MeetSpace — Android, Windows, Linux и веб-версия | 56 / 182 |
| `/download` | MeetSpace на своём сервере — ваша инфраструктура и данные | 57 / 171 |
| `/self-hosted` | Установка MeetSpace на свой сервер — руководство по Docker | 58 / 170 |

Open Graph использует соответствующие title/description каждой страницы.
Все canonical абсолютные; `/welcome` разделяет метаданные главной, а новые
страницы имеют собственные адреса. Числа в таблице — количество символов,
а не гарантия длины поискового сниппета.

По умолчанию используется подтверждённый публичный адрес
`https://meeting.janickiy.com`. При размещении на другом домене его необходимо
переопределить во время сборки:

```sh
cd frontend
VITE_PUBLIC_SITE_URL=https://meet.example.com npm run build
```

Значение должно быть абсолютным HTTP(S) origin без пути, параметров запроса,
фрагмента или встроенных учётных данных. Для публичной установки используйте
HTTPS. Переменная одинакова для клиентского кода и SSR-сборки. URL не
определяется по пользовательскому `Host` во время работы сайта.

Для `frontend/Dockerfile` предусмотрен аргумент `PUBLIC_SITE_URL`, который
передаётся как `VITE_PUBLIC_SITE_URL`:

```sh
docker build \
  --build-arg PUBLIC_SITE_URL=https://meet.example.com \
  --tag meetspace-frontend:local \
  frontend
```

Если образ собирается через Compose, передайте этот аргумент сборки для фактического
сервиса `frontend` или укажите его в `build.args` используемой конфигурации.
Переменная окружения работающего контейнера не меняет уже собранные canonical: после смены
домена нужна новая сборка веб-клиента.

`PublicMetadata` синхронизирует содержимое head при SPA-навигации и удаляет Open Graph,
canonical и структурированные данные при входе в приватную часть. `authenticated` для
корневого маршрута позволяет отличить лендинг от кабинета. При смене pathname
прокрутка возвращается наверх; URL с hash сохраняет переход к якорю. Язык
документа переключается на `en` для публичных страниц и `ru` для существующих
экранов авторизации и кабинета. Нейтральная приватная оболочка приложения сохраняет русский
язык и `noindex`.

Ссылки скачивания доступны в предварительно сформированном HTML. Манифест
содержит 9 проверенных файлов из официальных клиентских репозиториев: один
Android Universal APK, два Windows EXE и шесть Linux пакетов. Начальный выбор
даёт прямую закреплённую ссылку, а выбор архитектуры и формата обновляет её
после загрузки JavaScript. Статический HTML также содержит ссылки на оба
репозитория. Сведения о тестовом статусе beta/test и отсутствии цифровой подписи настольных сборок
показаны рядом со скачиваниями; цен, лицензий или гарантий совместимости в
структурированные данные не добавлено.

## Выдача и индексирование

`frontend/nginx.conf.template` явно выдаёт пять публичных документов, а остальные
SPA-маршруты используют `app.html`. OAuth callback также использует нейтральный
шаблон; его существующие правила журналирования сохранены. Поэтому HTML
страницы входа не наследует лендинг, canonical или индексируемый текст даже
без JavaScript. API и медиа-прокси не менялись.

Vite preview повторяет эту схему через плагин `public-static-preview`. Если
используется другой статический хостинг, необходимо перенести эквивалентные
правила: публичный HTML по точным маршрутам и выдача оболочки остальных страниц из `/app.html`. Для
`/download` и `/self-hosted`, как и остальных публичных страниц, предусмотрены
адреса с завершающим `/` и без него; canonical остаётся без завершающего `/`.

Сборка создаёт:

- `sitemap.xml` с четырьмя уникальными адресами: `/`, `/download`, `/self-hosted`
  и `/docs/self-hosted`; дубликат `/welcome` исключён;
- `robots.txt`, допускающий публичные страницы и необходимые статические
  ресурсы и запрещающий остальные URL.

Robots и `noindex` управляют индексированием, а доступ к данным по-прежнему
контролируется авторизацией приложения.

## Проверки текущей интеграции

`scripts/check-public-build.mjs` обновлён для пяти публичных документов. Он
проверяет один H1, русский HTML с кириллицей, `lang`, Open Graph locale,
JSON-LD, отдельный canonical для каждого маршрута, доступность локальных
ресурсов и путей к исходникам, внутренние ссылки и защиту внешних ссылок.

Проверка демонстрационной маркировки относится к главной и `/welcome`.
Проверка официальных клиентских репозиториев и прямых скачиваний относится
также к `/download`. Sitemap должен содержать ровно четыре уникальных
canonical-пути; robots разрешает обе новые страницы. Приватная оболочка приложения
проверяется на `noindex` и отсутствие публичного канонического адреса и публичного содержимого.

Для новой пятистраничной версии успешно выполнены `npm run build` и
`node scripts/check-public-build.mjs`. Во встроенном браузере подтверждены
семь карточек возможностей и 15 FAQ главной; на ширинах 360, 390, 750, 768,
1024, 1280, 1440 и 1920 нет горизонтального переполнения документа. Проверены
все три вкладки демо с клавиатурой, меню через Escape с возвратом фокуса и
закрытие по логотипу, а также выбор URL всех девяти установщиков. Ограниченная
проверка вычисленного контраста недекоративного текста после исправлений
не выявила нарушений; это не полноценный аудит WCAG.

В новой версии также проверены переходы на `/download`, `/self-hosted` и
`/docs/self-hosted`, мобильные страницы на 390px, инструкции и четыре FAQ
скачивания, копирование команд с подтверждением «Copied». Ошибок консоли
на проверенных публичных страницах нет. Прямые HTTP GET подтвердили новые
публичные адреса с завершающим `/` и без, их canonical, приватную оболочку приложения и
robots/sitemap (`product-routes.json`). Актуальные снимки главной:
`frontend/test-results/landing/product-desktop.jpg`, `product-full.jpg`,
`product-mobile.jpg`; журнал сборки — `product-build.log`.
