# Сборка технической документации MeetSpace

Редактируемый источник — `MEETSPACE_TECHNICAL_DOCUMENTATION_RU.md` в этой папке. PDF создаётся из него, а не редактируется отдельно. Схемы находятся в `assets/technical-documentation/`: это 16 исходных PNG без перерисовки или изменения разрешения.

## Подготовка

Нужны Python 3.10 или новее и зависимости из `tools/requirements-pdf.txt`. Из корня репозитория:

```bash
python3 -m venv .venv-docs
.venv-docs/bin/python -m pip install -r docs/tools/requirements-pdf.txt
```

На macOS сборщик автоматически использует полный набор Arial, Courier New и Arial Unicode из системной папки дополнительных шрифтов. На Linux используется DejaVu Sans и DejaVu Sans Mono. В Debian/Ubuntu шрифты можно установить командой:

```bash
sudo apt-get install fonts-dejavu-core
```

Для другой системы укажите `--font-dir /путь/к/шрифтам`. Нужны обычное, полужирное, курсивное и полужирное курсивное начертания обоих семейств. Названия файлов проверяются сборщиком; они перечислены в функции `register_fonts`.

## Сборка одной командой

После подготовки окружения, из корня репозитория:

```bash
.venv-docs/bin/python docs/tools/build_pdf.py
```

Результат — `docs/MEETSPACE_TECHNICAL_DOCUMENTATION_RU.pdf`. Все страницы, включая титульную и оглавление, имеют одинаковый альбомный формат A4. Встроенные ссылки оглавления ведут к разделам документа; рядом с PDF появляется файл `.render.json` с контрольными суммами, перечнем схем, шрифтов и предупреждений.

Пути по умолчанию определяются относительно самого скрипта, поэтому запуск из другой рабочей папки также поддерживается. Для отдельного предварительного результата:

```bash
.venv-docs/bin/python docs/tools/build_pdf.py --output /tmp/meetspace-preview.pdf
```

Сборщик не меняет Markdown, PNG, исходники приложения, историю Git или работающие серверы. Он записывает PDF и отчёт `.render.json` по выбранному пути. Существующий PDF заменяется, поэтому перед существенной редактурой сохраните его копию.

## Версия документа и воспроизводимость

Исходный срез документации — `main`, коммит `189631b5a50665c8c6b8725cfa21f3d46e895e52`. Дата текущей редакции текста — 28 октября 2026 года. Эти значения зафиксированы в сборщике; для новой редакции задайте `--commit`, `--date` (читаемая дата) и `--metadata-date` (дата в формате `YYYY-MM-DD`) и согласованно обновите метаданные Markdown.

Дата редакции не означает проверку развёрнутого приложения. Выполненные проверки и их ограничения описаны в `EDITORIAL_REPORT.md` и `DISCREPANCIES.md`.

При одинаковых исходниках, PNG, версиях библиотек и файлах шрифтов PDF собирается детерминированно: текущие время и случайный идентификатор не входят в результат. На другой платформе замена Arial на DejaVu может изменить переносы, число страниц и контрольную сумму. Чтобы получить побайтно одинаковый PDF, используйте те же шрифты, что указаны в `.render.json`, и то же окружение Python. Шрифты не включены в репозиторий; их лицензии нужно соблюдать отдельно.

Редкие символы, отсутствующие в выбранных шрифтах, выводятся как `U+...`, а их список сохраняется в `.render.json`. Исходные символы в Markdown не меняются. При текущей сборке это касается только четырёх символов в перечне реакций; команды и блоки кода таких замен не содержат.

## Проверка PDF

Для текстовых проверок достаточно установленных Python-зависимостей:

```bash
.venv-docs/bin/python docs/tools/check_pdf.py \
  --pdf docs/MEETSPACE_TECHNICAL_DOCUMENTATION_RU.pdf \
  --output-dir tmp/pdfs/documentation-check
```

Для визуальной проверки установите Poppler (`brew install poppler` на macOS или `sudo apt-get install poppler-utils` на Debian/Ubuntu), затем добавьте параметры:

```bash
.venv-docs/bin/python docs/tools/check_pdf.py \
  --pdf docs/MEETSPACE_TECHNICAL_DOCUMENTATION_RU.pdf \
  --output-dir tmp/pdfs/documentation-check \
  --render --contacts
```

Проверка создаёт отчёт о размерах страниц, выходе текста за поля, отсутствующих символах и встроенных изображениях, а также обзорные листы всех страниц и отдельные изображения сложных страниц. Для сравнения схем с предыдущей редакцией добавьте `--original /путь/к/предыдущей.pdf`.

После сборки просмотрите изображения страниц: автоматическая проверка границ не выявляет все случаи неудачного переноса или визуального наложения. Особое внимание уделите оглавлению, таблицам API и БД, схемам и длинным командам. Команда проверки сама по себе не является тестированием приложения.
