# MeetSpace Admin

Отдельная административная React/TypeScript SPA. Тёмная графитовая тема с мятным акцентом воспроизводит согласованный дизайн; доступна светлая тема. Все данные загружаются из административного API. Демонстрационных аккаунтов или фиктивных метрик в приложении нет.

## Сборка и проверка

Используйте Node.js, соответствующий `engines` в `package.json` (тот же диапазон, что у основного frontend).

```sh
cd admin
npm ci
npm test
npm run build
```

Результат — `admin/dist`. Приложение обслуживается из `/` отдельным Nginx HTTPS listener. Сборка не зависит от `frontend/dist`. Шрифты и иконки включены в локальные assets: внешние CDN не используются.

Для локальной разработки `npm run dev` запускает Vite на `127.0.0.1:5174`. Прокси `/api/v1/admin` направлен на `http://127.0.0.1:8082`; адрес можно задать `ADMIN_API_PROXY_TARGET`. Реальная авторизация требует HTTPS и точного `ADMIN_PUBLIC_URL`: для проверки сессий используйте административный TLS listener Nginx или локальный HTTPS reverse proxy. Не отключайте Secure cookies и проверки Origin ради dev-сервера.

## Границы сессии

- Браузер обращается только к same-origin `/api/v1/admin` с отдельной HttpOnly cookie.
- CSRF-токен из `login`/`me` хранится только в памяти и передаётся в `X-CSRF-Token` при мутациях.
- Все мутации имеют `Content-Type: application/json`, включая logout и DELETE.
- Пароли, cookie и токены не сохраняются в browser storage. Local Storage хранит только выбор темы; Session Storage — один несекретный флаг явного выхода, чтобы сетевой сбой при logout не восстанавливал cookie-сессию автоматически после перезагрузки.
- Ответ 401 очищает административный кеш и возвращает экран входа. Смена аккаунта отменяет старые запросы, удаляет их кеш и перемонтирует содержимое панели. Запоздалые ответы предыдущей сессии игнорируются.
- Поиск, фильтры, сортировка и пагинация выполняются сервером; запросы поддерживают AbortSignal.
- Чаты показывают только агрегированные числа. Журнал аудита не содержит операций изменения/удаления.
- Настройки сохраняются по группам. Доступные поля и их ограничения определяет API; остальные параметры доступны только для чтения. Значения секретов удаляются из ответов перед помещением в кеш. Пустое поле пароля SMTP сохраняет текущий пароль; новый пароль хранится только в памяти открытой формы и очищается после сохранения или ухода со страницы.

## Контракт API

`GET /auth/me` и `POST /auth/login` возвращают `{ administrator, csrfToken }`. Списки возвращают `{ items, total, page, pageSize }` и поддерживают `page`, `pageSize`, `q`, `status`, `sort`, `order`; журнал дополнительно использует `objectType`.

Типы ресурсов — в `src/types.ts`; обработка API — в `src/api.ts`. Нулевое значение отличается от отсутствующего: для `null`/непереданных метрик выводится «Нет данных».

`GET /settings` и успешный `PATCH /settings` возвращают `{ items, revision }`. Форма отправляет `{ revision, changes: { key: value } }` только для изменённых редактируемых полей выбранной группы. Размер вложений отображается в MiB и передаётся целым числом байт. Ответ 409 сохраняет введённые значения и требует явно загрузить актуальную конфигурацию перед повторным сохранением. SMTP и подтверждение email находятся в одной группе, чтобы переключатели можно было менять атомарно.

`npm test` проверяет передачу CSRF и cookies, истечение сессии, отмену запросов, гонки между сессиями, очистку кеша, явный выход при ошибке сети, кодирование фильтров, ограничение API одним origin, безопасные состояния удаления записей и валидацию учётных записей.

## Браузерные регрессии и проверка ресурсов

После `npm run build` доступны изолированные браузерные проверки. Они используют production-сборку и локальную HTTP fixture, не подключаются к данным платформы. Требуются установленный Google Chrome и доступный Node-модуль `playwright`; если он установлен вне `admin/node_modules`, задайте `PLAYWRIGHT_MODULE_PATH` абсолютным путём к модулю. Новые runtime-зависимости для приложения не требуются.

```sh
npm run test:browser
npm run test:browser:cycles
npm run test:browser:soak
node tests/browser/settings.cjs dist
```

Первая команда проверяет ошибки logout, смену аккаунта без показа предыдущего кеша, запоздалый ответ `/auth/me`, восстановление фокуса после модального действия, остановку polling при смене раздела и состояния 403/503/empty/retry. Вторая выполняет 100 переходов, 50 циклов модального окна и 10 входов/выходов. Третья запускает ограниченную проверку Dashboard на 30 минут с обычным polling. Команды `cycles` и `soak` записывают в игнорируемый Git каталог `test-results` только числовые метрики heap/DOM/listeners после GC, количество запросов и ошибки JavaScript. Cookie, пароли и содержимое запросов в отчёт не попадают. Результаты fixture не заменяют HTTPS E2E с реальным backend.

Проверка `settings.cjs` покрывает числовую валидацию и MiB, сохранение по группам, отказ API без ложного success, конфликт версий, SMTP/подтверждение email, сохранение текущего пароля при пустом поле, очистку секретного черновика и отмену запроса при навигации. Она также проверяет мобильную ширину и сохраняет диагностические изображения формы с синтетическими данными в `test-results`.
